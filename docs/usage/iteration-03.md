# И03: JupyterHub → браузер → приёмник

Один монохромный QR, зашифрованный 7z, периодическая metadata и циклический показ.
После обновления до 0.4 используйте также [инструкцию И04](iteration-04.md):
новый capture сохраняет SQLite и поддерживает resume; ниже описан исходный сценарий И03.
Проверки на реальном VDI выполняем совместно для И00–И03, как согласовано.
[Профиль и ограничения](../specs/mono-player.md) · [Локальный отчёт](../reports/browser-mono.md)

## 1. Отправитель: терминал JupyterHub

Из корня обновлённого репозитория, в выбранном окружении Python 3.10:

```bash
python -m pip install ".[sender]"
python -m qr_transfer pack artifacts/i00/fixtures/tree --output artifacts/i03/prepared
python -m qr_transfer render artifacts/i03/prepared/object.7z --descriptor artifacts/i03/prepared/descriptor.json --output artifacts/i03/player
```

`pack` запрашивает пароль с подтверждением. Вместо тестового `tree` можно указать
свой файл/каталог. `render` читает уже зашифрованный объект, пароль ему не нужен.
В консоли виден ход подготовки QR. Для повторных прогонов нужны новые выходные
каталоги; существующие результаты не перезаписываются.

Проверить размер/длительность цикла заранее, без генерации кадров:

```bash
python -m qr_transfer render artifacts/i03/prepared/object.7z --descriptor artifacts/i03/prepared/descriptor.json --output artifacts/i03/player --estimate
```

Для большого объекта доступен `--external-only`: он создаёт `index.html`,
`frames.bin` и папку `parts-*` без автономной копии. JavaScript встроен в HTML,
матрицы загружаются порциями. [Новые лимиты и проверка больших файлов](paged-vdi-test.md).
Для первых проверок используйте автономный вариант.

## 2. Открыть плеер в браузере VDI

Откройте **`artifacts/i03/player/standalone.html` отдельной вкладкой браузера**.
В адресе JupyterLab замените `/lab/tree/` на `/files/`, сохранив пользовательский
префикс и путь к файлу. Этот способ уже позволил открыть fullscreen на данном VDI.
Если маршрут скачивает HTML, откройте скачанный файл браузером на самом VDI.

Дождитесь сообщения «Архив загружен». Нажмите «Полный экран»; сверху по умолчанию
оставлено **48 CSS px** под панель подключения. Если нужно, выйдите через Esc,
увеличьте отступ до 64/96/128 и снова включите полный экран.

Плеер пока стоит на первом кадре. Запустите приёмник на хосте, затем нажмите Старт.
В полном экране Space переключает показ/паузу, Esc выходит. Скорость, шаг и возврат
к началу доступны в оконном режиме. На паузе последний кадр сохраняется. При
скрытии вкладки показ останавливается; после возвращения нажмите Старт.

Передача идёт по кругу, пока вы её не остановите. Плеер не знает, завершён ли приём.
Изменение интервала или повторный Старт не требуют упаковки/подготовки заново.
Повторный `render` создаёт новый ID передачи — для него используйте новый каталог
состояния приёмника.

## 3. Приёмник: текущий Windows-хост, монитор 1

В PowerShell из корня репозитория:

```powershell
.\.venv-i00\Scripts\python.exe -m pip install ".[receiver]"
.\.venv-i00\Scripts\python.exe -m qr_transfer monitors
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --monitor 1 --state artifacts/i03/vdi-tree-1 --extract-to artifacts/i03/restored-tree-1
```

Монитор 1 на проверенном хосте — основной 3840×2160. QR должен быть полностью виден,
включая белую рамку. Плеер и декодер работают с одним QR; ROI/multi-QR добавляются в И04.

В консоли видны уникальные чанки, новые полезные байты/с (среднее с начала приёма),
фактическая частота захвата, повторы и ошибки. После всех чанков проверяются размер
и SHA-256 архива, захват прекращается и появляется скрытый запрос пароля.
Правильный пароль завершает распаковку, результат содержит исходный корень `tree`.

Неправильный пароль не требует повторять передачу. После исчерпания попыток:

```powershell
.\.venv-i00\Scripts\python.exe -m qr_transfer unpack artifacts/i03/vdi-tree-1/object.bin --descriptor artifacts/i03/vdi-tree-1/status.json --output artifacts/i03/restored-tree-1
```

Если нужен только зашифрованный объект, не указывайте `--extract-to`.
Существующий выход распаковки не заменяется — выберите новое имя.

## Таймауты, результат и отмена

- `--fps 12`: целевая частота захвата; реальная измеряется отдельно.
- `--first-timeout 120`: ожидание первого валидного потока.
- `--idle-timeout 600`: отсутствие новых данных. Дубликаты не продлевают ожидание. Для больших объектов или замедленного показа задайте лимит больше длительности полного цикла с запасом.
- `--total-timeout 0`: общего ограничения по умолчанию нет; при необходимости
  задайте число секунд. Обычная длинная передача не обрывается на 300-й секунде.
- Ctrl+C сохраняет журнал и состояние, возвращает 130.

Коды `capture`: **0** — выбранные этапы завершены; **2** — таймаут/неполный объект;
**1** — ошибка захвата/целостности/параметров; **3** — архив принят, распаковка не
завершилась; **130** — отмена. Команда `unpack` отдельно использует коды И02.

В `--state` остаются `status.json`, `capture.json`, журнал принятых пакетов, чанки,
а после успешного приёма — `object.bin`. При `--extract-to` появляется также
`extraction.json`. Пароль в них не сохраняется. Незавершённые чанки сохраняются,
но подключение живого захвата к старому состоянию — И04; новый `capture` требует
нового каталога. Снимки рабочего стола на диск не записываются.

## Совместная проверка после И03

1. На JupyterHub проверить установку, скрытый ввод, подготовку файла и каталога.
2. На VDI проверить новый fullscreen-отступ и отсутствие перекрытия QR.
3. Выполнить три приёма объекта около 1 МиБ при Full HD, каждый в новый каталог.
4. Один приём начать посреди цикла; один раз ввести неправильный пароль, затем правильный.
5. Сохранить `prepare.json`, отчёт плеера и `capture.json` каждого прогона; записать
   масштаб ОС/браузера/VDI и фактический режим экрана. Само наличие экрана 4K не
   превращает прогон в Full HD; CSS-размер не подтверждает число пикселей на хосте.

Локальные автоматические проверки доступны отдельно:

```powershell
.\.venv-i00\Scripts\python.exe -m unittest discover -s tests -v
.\.venv-i00\Scripts\python.exe tools/check_i03_player.py --output artifacts/i03/check --size-kib 1024 --runs 3
```

Browser-стенд требует также `.[qr]`, Playwright, psutil и установленный Chrome. Его прогоны
с пошаговым переключением не являются измерением скорости VDI.
