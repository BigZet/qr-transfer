# И04: два QR, область захвата и возобновление

[Результаты](../reports/receiver-multiqr.md) · [Хранение и pipeline](../specs/receiver-state.md)

## Отправитель в JupyterHub

Обновите репозиторий и установите отправитель в выбранное окружение Python 3.10:

```bash
python -m pip install ".[sender]"
python -m qr_transfer render artifacts/i03/prepared/object.7z --descriptor artifacts/i03/prepared/descriptor.json --output artifacts/i04/player --slots 2 --update-mode sync
```

Можно использовать уже подготовленный архив И03: повторно вводить пароль и
сжимать исходник не нужно. Для нового файла используйте `pack` по инструкции И03.
Новый `render` создаёт новый ID передачи, поэтому для него нужен новый каталог
приёмника. Для продолжения используйте **тот же HTML**, а не заново созданный.

Откройте `artifacts/i04/player/standalone.html` отдельной вкладкой браузера VDI
через ранее проверенный маршрут `/files/`. Включите полный экран. По умолчанию
сверху остаётся 48 CSS px под панель подключения.

В оконном режиме можно переключать **1×1 / 2×1** и **одновременно / поочерёдно**.
Это сохраняет ID и пакетизацию. При Full HD/DPR=1 два QR занимают 1858×925 px:
по 925 px на QR с тихой зоной и зазор 8 px. Если двум QR достаётся меньше
4 пикселей на модуль, но один помещается с масштабом ≥4, плеер выбирает один QR.
Фактическое число видно в статистике.

Интервал означает период обновления **каждого слота**. При двух слотах и 600 мс
одновременный режим меняет оба каждые 600 мс; поочерёдный меняет один каждые
300 мс. Оба предлагают одинаковое число новых кодов в секунду.

Для больших объектов добавьте `--external-only` и откройте `index.html` вместе
с `player.js`/`frames.bin` по HTTP-маршруту JupyterHub. Автономный вариант ограничен
8 МиБ матриц, отдельные ресурсы — 32 МиБ. `--estimate` показывает бюджет заранее.

## Приём на Windows

```powershell
.\.venv-i00\Scripts\python.exe -m pip install ".[receiver]"
.\.venv-i00\Scripts\python.exe -m qr_transfer monitors
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --monitor 1 --state artifacts/i04/vdi-1 --extract-to artifacts/i04/restored-1
```

После запуска приёмника начните показ. Он считывает все QR, сохраняет уникальные
пакеты, проверяет архив и запрашивает пароль. Поле `committed` показывает число
чанков, транзакция которых уже сохранена. Сообщение об отсутствии новых данных
предлагает проверить видимость, масштаб и область; дубликаты не считаются прогрессом.

### Продолжить после Ctrl+C, таймаута или аварии

```powershell
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --monitor 1 --state artifacts/i04/vdi-1 --resume --extract-to artifacts/i04/restored-1
```

Оставьте тот же плеер. Приёмник перепроверит сохранённые пакеты и будет ждать
недостающие. Если архив уже собран, захват не потребуется: сразу начнётся этап
пароля. Существующий каталог распаковки не заменяется.

`--resume` предназначен для **новых сессий И04 с packets.sqlite3**. Незавершённые
сессии И03 с `accepted.aqs` автоматически не мигрируют; начните для них новый
приём. Уже принятые в И03 архивы по-прежнему распаковываются командой `unpack`.

### Ограничить область захвата

```powershell
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --monitor 1 --roi 100 80 1800 950 --state artifacts/i04/roi-1
```

Четыре числа — **X Y ширина высота**, в физических пикселях относительно левого
верхнего угла выбранного монитора. Это не CSS и не координаты удалённого рабочего
стола. Область должна вмещать оба QR с белыми рамками. Числа выше — пример,
подберите их под положение окна; полный монитор работает без `--roi`.

Для монитора с отрицательным положением на рабочем столе X/Y остаются локальными
неотрицательными числами: смещение монитора прибавляется автоматически. При
возобновлении можно изменить monitor/ROI без изменения пакетной сессии.
После уменьшения монитора, если заданная ROI перестала помещаться, приёмник
временно захватывает весь монитор и записывает `roi_fallback_full_monitor=true`.
Исчезновение выбранного монитора завершает захват с ошибкой; затем задайте
доступный монитор и возобновите ту же сессию.

### Состояние и диагностика

```powershell
.\.venv-i00\Scripts\python.exe -m qr_transfer inspect artifacts/i04/vdi-1
.\.venv-i00\Scripts\python.exe -m qr_transfer inspect artifacts/i04/vdi-1 --verify-state
```

Первая команда читает последний `status.json`. Вторая эксклюзивно открывает сессию,
проверяет SQLite/пакеты, восстанавливает кэш и обновляет статус. Не запускайте её
одновременно с приёмом. `missing_ranges` содержит включительные диапазоны
индексов недостающих чанков с нуля.

Таймауты прежние: первый поток 120 с, отсутствие новых данных 600 с, общий лимит
отключён. После resume отсчёт начинается заново, скорость учитывает только новые
байты этого запуска. Для длинного цикла увеличьте `--idle-timeout` с запасом.

`capture.json` содержит времена, RSS при установленном psutil, счётчики позиций,
поиска и очереди; это отчёт последнего запуска. Скопируйте его перед новым замером,
если нужны все попытки. `status.json` обновляется примерно раз в секунду и при
закрытии; источник истины — SQLite. `.writer.lock` остаётся на диске штатно:
удалять его для resume не нужно, владение определяется блокировкой ОС.

Для сравнения есть `--sync` (последовательный захват/декодирование), `--no-cache`
(полный поиск каждого снимка), `--queue-size 1` или `2` (по умолчанию 2).
Снимки рабочего стола на диск не записываются. Очистка состояния выполняется
только вручную после остановки процессов и проверки выбранного каталога.

## Проверка на VDI

1. Сравните один QR и оба расписания двух QR на одном архиве, разрешении и интервале.
2. Прервите приём после части чанков и продолжите с `--resume`.
3. Переместите окно/измените масштаб, затем восстановите читаемый размер.
4. Сохраните отчёт плеера и `capture.json`, зафиксируйте разрешение и ROI.

Локальные проверки выполняются без VDI:

```powershell
.\.venv-i00\Scripts\python.exe -m unittest discover -s tests -v
.\.venv-i00\Scripts\python.exe tools/check_i04_receiver.py --output artifacts/i04/check-new
```

Стенд требует также Playwright, psutil и Chrome. Его результаты не заменяют
реальное сравнение канала VDI; прежний критерий 1 МиБ при Full HD остаётся открытым.
