# Проверка порционной загрузки на VDI

При ошибке загрузки через `/files/` см. [запуск через Jupyter proxy](jupyter-player.md).
В некоторых конфигурациях Jupyter изолирует и отдельную вкладку HTML.

## Что изменилось

`index.html` загружает QR-матрицы порциями, проверяя размер и CRC каждой. В браузере
не более четырёх готовых порций и одной загружаемой. По умолчанию порция содержит
256 матриц (около 0,96 МиБ), буфер матриц ограничен примерно 4,79 МиБ. При задержке
текущий QR остаётся на экране, кадры не перескакивают. Новая порция загружается
заранее для следующего показа. HTTP Range не требуется.

По умолчанию генерация QR выполняется полностью перед открытием плеера.
Для параллельной подготовки и раннего старта используйте
[ускоренную генерацию](fast-generation.md). Исходный `frames.bin` сохраняется для обновления/проверки,
поэтому вместе с порциями на сервере матрицы занимают примерно двойной объём.

Repeat теперь допускает архив до **64 МиБ** через порционный index. Лимит LT
остаётся **16 МиБ** из-за текущего формата/числа блоков. Standalone по-прежнему
ограничен 8 МиБ матриц. Исходные/распакованные данные — до 256 МиБ и 10 000 записей.

## Вариант А: уже подготовленный большой плеер

Обновите репозиторий на VDI. Из его корня:

```bash
python tools/refresh_player.py artifacts/i06/player-large --paged --part-frames 64
```

Укажите свой существующий каталог. HTML резервируется, матрицы проверяются и
разбиваются на небольшие файлы. Архив и ID передачи не меняются, QR повторно
не генерируются. Откройте обновлённый `index.html` через `/files/` и нажмите
Ctrl+Shift+R. Не переносите один HTML отдельно от созданной папки `parts-*`.

Продолжайте приём с прежним транспортом и цветом. Если состояние уже начато,
используйте прежний `--state` и `--resume`; сохраните старые отчёты до повторного
запуска. Дальнейшая команда теста Б предназначена для **новой** передачи repeat.

## Вариант Б: воспроизводимый тест 10 МиБ

Данные синтетические, плохо сжимаются. Проверка на хосте независимо вычисляет
ожидаемый SHA-256, исходный файл на хост переносить не требуется.

### 1. На VDI / JupyterHub

```bash
python -m pip install ".[sender]"
python tools/paged_fixture.py create artifacts/paged-vdi/source/test-10m.bin --mib 10
python -m qr_transfer pack artifacts/paged-vdi/source/test-10m.bin --output artifacts/paged-vdi/prepared
python -m qr_transfer render artifacts/paged-vdi/prepared/object.7z --descriptor artifacts/paged-vdi/prepared/descriptor.json --output artifacts/paged-vdi/player --transport repeat --visual rgb8 --slots 2 --interval-ms 600 --part-frames 64 --external-only --estimate
python -m qr_transfer render artifacts/paged-vdi/prepared/object.7z --descriptor artifacts/paged-vdi/prepared/descriptor.json --output artifacts/paged-vdi/player --transport repeat --visual rgb8 --slots 2 --interval-ms 600 --part-frames 64 --external-only
```

При `pack` задайте пароль. Каталоги вывода должны быть новыми. Подготовка нескольких
тысяч QR может занять минуты; дождитесь завершения `render`. Откройте
`artifacts/paged-vdi/player/index.html` отдельной вкладкой через `/files/`.
Включите fullscreen и оставьте верхний отступ под панель VDI.

Плеер готов после первой порции, не после загрузки всех матриц. На странице,
в том числе в fullscreen, виден **ориентир времени полного цикла** и остаток
до конца текущего цикла. Начальная оценка учитывает цвет/слоты/частоту и служебные
кадры, затем уточняется по фактическим интервалам показа. Это не подтверждённое
время завершения приёмника: при потерях нужны повторы; LT может завершиться раньше.
При паузе остаток указан без времени паузы. Окончание цикла не останавливает показ.

### 2. На Windows, монитор 1

```powershell
.\.venv-i00\Scripts\python.exe -m pip install ".[receiver]"
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --transport repeat --visual rgb8 --monitor 1 --state artifacts/paged-vdi/receive-1 --extract-to artifacts/paged-vdi/restored-1
```

После запуска приёмника нажмите **Старт** в браузере VDI. Дождитесь подтверждения
архива, введите пароль и завершите распаковку. Затем проверьте точность файла:

```powershell
.\.venv-i00\Scripts\python.exe tools/paged_fixture.py verify artifacts/paged-vdi/restored-1/test-10m.bin --mib 10
```

Ожидается `verified: true`. Если цвет не проходит, остановите приёмник, выберите
моно в том же плеере и продолжите с `--visual mono --resume`, тем же каталогом
состояния и прежним транспортом. Часть уже принятых пакетов сохранится.

### 3. Проверки порций

- Сохраните JSON плеера в начале и после нескольких переходов между порциями.
- `paging.enabled=true`, `cached_parts<=4`. Для `--part-frames 64` верхняя граница
  `peak_buffer_bytes` — **1 257 357 байт** (кэш матриц и загружаемая порция, не вся
  память вкладки). Число `requests` растёт во время показа; весь набор не читается
  при старте. При новом цикле вытесненные порции запрашиваются снова.
- Пауза/Старт должны продолжать показ. При смене моно/4/8 цветов и слотов время
  пересчитывается, ID остаётся прежним.
- Если порция недоступна или повреждена, плеер останавливается с сообщением.
  После восстановления файлов нажмите **Старт**; если ошибка возникла до готовности
  первой порции, обновите страницу. Не удаляйте порции во время
  обычной передачи; сценарий повреждения уже проверен локально.
- Сохраните `capture.json`, `status.json`, `extraction.json` **до повторного resume**,
  а также JSON плеера, масштаб и разрешение VDI. Отчёты приёмника перезаписываются.

## Тест выше прежнего ограничения repeat

Для проверки архива больше прежних ~22,9 МиБ используйте **32 МиБ**:
`paged_fixture.py create .../test-32m.bin --mib 32`, затем тот же pack/render с
новыми каталогами и `--transport repeat`. На хосте проверяйте `--mib 32` и новое
имя файла. Передача будет дольше; ориентир появится в плеере и `--estimate`.
Порционная загрузка уменьшает память/ожидание браузера, а не длительность QR-канала.

## Локальный стенд

```powershell
.\.venv-i00\Scripts\python.exe tools/check_paged_player.py --output artifacts/paged/local-new
```

Проверяет HTTP → порции → repeat/LT → распаковку → точное сравнение, границы
порций, вытеснение кэша, новый цикл и смену цвета. Требуются Chrome/Playwright и
extras sender,receiver,fec. Локальные результаты не подменяют проверку VDI.
