# Использование

[Установка и первый запуск](../../README.md). Все команды выполняются из корня
репозитория с Python соответствующего виртуального окружения.

## Подготовка и показ

`pack` принимает файл или каталог. Пароль вводится скрыто; требуется на приёмнике.
`render` получает object.7z и descriptor.json из одной подготовки.

- `--workers 0`: автоматически до четырёх процессов с учётом доступных CPU;
  явное значение 1..16. Квота JupyterHub может ограничивать ускорение.
- `--live --external-only`: начать после первой готовой порции.
- `--part-frames 32`: небольшой буфер старта, диапазон 8..1024.
- `--visual mono|rg4|rgb8`: один, два или три слоя данных.
- `--slots 1|2`, `--interval-ms 300`: раскладка и интервал; минимум 50 мс.
  Минимальное значение не гарантирует максимальную полезную скорость.
- `--estimate`: оценка объёма матриц и цикла без генерации QR.

Если показ догоняет генератор, текущий QR остаётся до готовности следующего.
Время на экране относится к циклу, а не подтверждённому завершению приёма.
Без --live сначала готовится весь набор. Standalone содержит все данные внутри;
для больших наборов используйте порционный index через /proxy/.

## Возобновление

```powershell
.\.venv\Scripts\python.exe -m qr_transfer capture --transport repeat --visual rgb8 --monitor 1 --state artifacts/receive/session-1 --resume --extract-to artifacts/receive/restored-2
```

Используйте прежний плеер и состояние. После нового render требуется новый каталог
состояния. Цвет можно сменить на обеих сторонах без смены транспорта/ID.
Перед повторным resume сохраните capture.json: он перезаписывается.
Вывод распаковки должен быть новым каталогом. Не запускайте два приёмника на одно
состояние. При неверном пароле повторите unpack, передавать архив заново не нужно:

```bash
python -m qr_transfer unpack artifacts/receive/session-1/object.bin --descriptor artifacts/receive/session-1/status.json --output artifacts/receive/restored-2
```

## Ошибки

capture.json содержит termination, прогресс и error. Для исключения сохраняются
stage (capture/decode/receive/status/progress), тип, цепочка причин, файл/функция/строка,
коды ОС. Пароли, байты пакетов и произвольный текст исключений не сохраняются.
extraction.json отдельно фиксирует завершение распаковки.

При отсутствии прогресса проверьте выбранный монитор, полный экран, верхний отступ,
видимость всех QR и цветовых образцов. Увеличьте интервал или перейдите на mono.
Успешная сборка определяется SHA-256, а не количеством циклов или таймером.

## LT (экспериментальный)

Установите дополнение fec на обеих сторонах: `pip install ".[sender,fec]"` и
`pip install ".[receiver,fec]"`. Укажите --transport lt в render и capture.
LT имеет конечный пул repair-пакетов; повторение одного пула не создаёт новых
независимых уравнений. Увеличение repair_factor увеличивает подготовку и цикл.
Крупный VDI-приём ранее завершился ошибкой; основной рабочий сценарий — repeat.
Журнал LT можно продолжать с --resume и прежним плеером. Для локальной диагностики
копии журнала доступен `python tools/check_lt_resume.py --help`.

## Проверка тестового файла

```bash
python tools/paged_fixture.py create artifacts/test/source.bin --mib 10
```

Упакуйте source.bin и передайте по инструкции README. На хосте:

```bash
python tools/paged_fixture.py verify artifacts/receive/restored-1/source.bin --mib 10
```

Ожидается verified=true. Файл детерминированный, перенос эталона на хост не нужен.
