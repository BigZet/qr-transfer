# Плеер в JupyterHub

## Рабочий маршрут через proxy

Из корня репозитория в отдельном терминале JupyterHub:

```bash
python tools/serve_player.py artifacts/send/player --port 8765
```

Откройте напечатанный путь на том же домене и порту JupyterHub. Например,
`/user/<user>/<server>/proxy/8765/index.html`. Терминал оставьте работающим.
Сервер слушает только 127.0.0.1 и обслуживает выбранный каталог. Не открывайте
127.0.0.1 в браузере Windows, если JupyterHub работает на другой машине.

Нужно включённое расширение jupyter-server-proxy в окружении работающего сервера,
не только в виртуальном окружении отправителя. Проверка: `jupyter server extension list`
(старые версии: `jupyter serverextension list`). Сам список не доказывает доступность
маршрута; откройте URL работающего плеера. При 404 проверьте префикс и расширение,
при 502/503 — работающий процесс и номер порта.
[Документация proxy](https://jupyter-server-proxy.readthedocs.io/en/latest/arbitrary-ports-hosts.html).

## Почему /files/ может не работать

Jupyter может выдавать HTML с CSP sandbox allow-scripts: встроенный JS выполняется,
но читать соседние порции он не может даже в отдельной вкладке. Плеер диагностирует
origin=null. Политики Jupyter отключать не требуется: используйте /proxy/.
Для небольшого полностью встроенного набора можно standalone.html.

Не копируйте index отдельно от папки parts-*. В live оставьте также работающим
терминал render. При ожидании генерации плеер сохраняет текущий кадр.

После завершения render можно обновить HTML без повторной генерации матриц:

```bash
python tools/refresh_player.py artifacts/send/player
```

Будет создана резервная копия HTML; transfer ID останется прежним. Во время
незавершённой генерации эту команду не запускайте. После обновления — Ctrl+Shift+R.
