# И05: восстановление потерянных QR

Добавлен отдельный транспорт `lt`: исходные и восстановительные пакеты LT-code.
Первый малый LT-архив проверен на хосте; сравнительные замеры И04/И05 остаются открытыми.
[Результаты](../reports/fec.md) · [Протокол и ограничения](../specs/aqr2-lt.md).

## Подготовка в JupyterHub

Обновите репозиторий и установите зависимости в Python 3.10:

```bash
python -m pip install ".[sender,fec]"
python -m qr_transfer render artifacts/i03/prepared/object.7z --descriptor artifacts/i03/prepared/descriptor.json --output artifacts/i05/player --transport lt --slots 2
```

Используйте уже зашифрованный архив либо подготовьте новый командой `pack` из И03.
Откройте `artifacts/i05/player/standalone.html` отдельной вкладкой браузера VDI.
Fullscreen, верхний отступ, пауза, скорость и два QR работают как в И04.

По умолчанию внутри каждой группы блоков сначала идут исходные символы,
затем repair-пакеты, способные восстановить часть пропусков. Режим сравнения,
состоящий только из repair, включается через `--fec-mode repair-only`.
`--repair-factor 3` задаёт максимум 3K repair-пакетов на блок с K исходными
символами; доступны также 1 и 2. Меньший пул может не восстановить блок даже
после многократного повторения всех его пакетов.

**Это конечный пул, а не бесконечный fountain-поток.** Плеер повторяет заранее
подготовленный набор. Один и тот же repair-пакет второй раз не добавляет информации.
Если набор недостаточен, используйте больший коэффициент или systematic-режим
при новом `render` и новом состоянии приёмника. Repeat остаётся режимом по умолчанию
и может быть быстрее на хорошем канале.

Для крупных файлов сначала проверьте бюджет:

```bash
python -m qr_transfer render artifacts/i03/prepared/object.7z --descriptor artifacts/i03/prepared/descriptor.json --output artifacts/i05/player-large --transport lt --slots 2 --estimate
```

LT ограничен архивом 16 МиБ. Для больших наборов добавьте `--external-only` и
откройте `index.html` по HTTP-маршруту JupyterHub, сохранив рядом папку `parts-*`.
Новый index читает матрицы порциями; общий бюджет — 256 МиБ матриц,
8 МиБ матриц для автономного HTML; Base64 увеличивает
размер примерно на треть. Все QR генерируются до готовности страницы, поэтому
на крупных объектах подготовка может занять минуты. Пока она не закончилась,
не открывайте частично созданный комплект.

## Приёмник Windows, монитор 1

```powershell
.\.venv-i00\Scripts\python.exe -m pip install ".[receiver,fec]"
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --transport lt --monitor 1 --state artifacts/i05/vdi-1 --extract-to artifacts/i05/restored-1
```

Приёмник показывает принятые символы и восстановленные блоки. Точного обещания
«осталось N пакетов» нет: разные LT-символы могут быть зависимыми. Новые полезные
байты появляются в статистике после восстановления блока. В конце проверяются
размер/SHA-256 всего архива, затем запрашивается пароль и выполняется распаковка.

Продолжение той же передачи:

```powershell
.\.venv-i00\Scripts\python.exe -m qr_transfer capture --transport lt --monitor 1 --state artifacts/i05/vdi-1 --resume --extract-to artifacts/i05/restored-1
.\.venv-i00\Scripts\python.exe -m qr_transfer inspect artifacts/i05/vdi-1 --verify-state
```

Если файлы уже распакованы, при повторном `capture --resume` уберите
`--extract-to`: существующий каталог не перезаписывается. Для повторной распаковки
выберите новый путь. `capture.json` и `extraction.json` описывают последние вызовы;
перед повторным запуском сохраните копии, если нужны исходные результаты замера.
Повторный запуск завершённой сессии не измеряет скорость передачи.

Последнюю команду запускайте после остановки приёмника. Она определяет тип
хранилища по файлам сессии. Журнал `fec.sqlite3` сохраняет уникальные валидные
символы; состояние декодера воспроизводится из него. `blocks/*.bin` — восстановленные
части, `object.bin` — проверенный архив. Время восстановления записывается в
`resume_seconds`. Для resume нужен прежний плеер/ID и прежний `--transport lt`.
Смена скорости и количества QR не меняет пакетизацию; новый `render` меняет ID.

Параметры ROI, очереди и таймаутов — как в И04. Для длинного полного цикла увеличьте
`--idle-timeout` с запасом. После таймаута не требуется заново принимать уже
сохранённые символы. Неверный пароль исправляется через `unpack` принятого объекта.

## Зависимость LT-code

Закреплена `lt-code==0.3`, чистый Python. В публичном PyPI поставляется исходный
архив; локально из него собран переносимый `lt_code-0.3-py3-none-any.whl`.
Внутреннее зеркало JupyterHub ещё предстоит проверить. При необходимости соберите
wheel в окружении с доступом к пакету и перенесите его вместе с проектом:

```bash
python -m pip wheel --no-deps lt-code==0.3 --wheel-dir artifacts/i05/wheels
python -m pip install artifacts/i05/wheels/lt_code-0.3-py3-none-any.whl
```

RaptorQ/Wirehair для этого профиля устанавливать не нужно. Причины выбора и
проверенные ошибки установки сохранены в отчёте.

## Совместная проверка после И05

1. На одном архиве сравните repeat и LT при одинаковой скорости, 1×1 и 2×1.
2. Один приём начните посреди цикла, один прервите и продолжите с `--resume`.
3. Проверьте перенос окна, ROI и масштаб; записывайте физическое разрешение хоста.
4. Сохраните `prepare.json`, отчёт плеера и `capture.json` до следующего запуска.

Сравнение на 1/10 МиБ и прежний критерий Full HD ещё открыты. Локальный стенд:

```powershell
.\.venv-i00\Scripts\python.exe tools/check_i05_fec.py --output artifacts/i05/comparison-new
.\.venv-i00\Scripts\python.exe tools/check_i05_fec.py --output artifacts/i05/browser-new --browser-only
```

Первый сохраняет все 540 попыток и трассы потерь. Второй требует Playwright,
psutil и Chrome и проверяет браузер → декодер → архив → исходные файлы без VDI.
