# AQR2-LT v1: конечный пул межпакетного FEC

Профиль 2 использует готовые `lt.encode.encoder`, `lt.decode.BlockGraph` и
`lt.sampler.PRNG` из **lt-code 0.3**. Математика fountain не реализуется заново.
Параметры распределения фиксированы: `c=0.1`, `delta=0.5`; начальное состояние
генератора 2067261 для каждого независимого блока. Систематические символы
передаются как одноэлементные уравнения в тот же готовый BlockGraph.

## Обёртка пакета

Сохраняется 44-байтовая структура заголовка AQR2 и CRC-32 всего пакета с нулём
в поле CRC при расчёте. `profile=2`, версия descriptor=1, flags=0. Парсер repeat
профиля 1 не принимает эти пакеты; форматы не смешиваются автоматически.

| Поле | Смысл в профиле 2 |
| --- | --- |
| kind=0 | bootstrap, index=0, payload ≤900 байт |
| kind=1 | исходный символ, payload 2800 байт |
| kind=2 | repair: seed uint32 BE + 2800 байт XOR-данных |
| index uint32 | block ID в старших 8 битах, ordinal в младших 24 |
| total uint32 | число source blocks, 1…256 |
| transfer_id | 16 байт, новый при каждой подготовке |

Для source ordinal=0…K−1, для repair=0…factor*K−1. Source/repair с одинаковым
ordinal — разные пакеты. Seed repair лежит в диапазоне 1…2147483646.
Размер QR-пакетов — 2844/2848 байт; оба помещаются в V40-L/byte mode.
CRC-повреждения отклоняются до backend. Конфликт одинакового ключа и разных
байтов завершает capture с ошибкой.

Bootstrap — строгий JSON с полями `object`, `k`, `repair_factor`, `mode`,
`scheme="lt-code-0.3-v1"`, `symbol_size=2800`. Неизвестные/повторяющиеся поля
отклоняются. `object` содержит существующий технический TransferDescriptor И02
для проверки/распаковки архива. Его историческое поле `transport=aqr2-repeat`
сохранено для совместимости контейнерного API; реальный транспорт определяется
**внешним profile=2 и scheme**, а не этим вложенным полем.

## Блоки и восстанавливаемая оболочка

Архив ≤16 МиБ, номинальный K=min(32,max(2,ceil((object_size+1024)/2800))).
Вместимость блока данных — `K*2800−1024`. Для последнего блока число символов
уменьшается до `ceil((остаток+1024)/2800)`.

Первые 1024 байта каждого восстанавливаемого блока:

1. ASCII `LTB1`.
2. block ID uint32 BE.
3. длина canonical bootstrap uint32 BE.
4. canonical bootstrap (`sort_keys`, компактный JSON), затем нули до 1024 байт.

Далее байты зашифрованного архива; хвост до полного символа дополняется нулями.
После декодирования проверяются точное совпадение префикса и нулевой padding,
данные обрезаются до объявленной длины. Сборка всех блоков обязательно проверяет
размер и SHA-256 до выдачи результата контейнерному модулю. CRC/FEC не заменяют
шифрование и проверку архива.

Bootstrap повторяется каждые 8 визуальных символов. Его копия внутри каждого
восстановленного блока проверяет согласованность, но не отменяет необходимость
получить хотя бы один внешний bootstrap до декодирования. Зависимости «сначала
декодировать metadata, чтобы начать декодирование» нет.

## Расписание и конечность

Python готовит группы максимум из 8 блоков. В systematic-режиме сначала исходные
символы чередуются по блокам, затем отдельно чередуются repair. Короткий последний
блок не начинает repair до завершения source-фазы группы. Repair-only пропускает
source-фазу. По умолчанию factor=3, допустимы 1…3.

Все матрицы предварительно генерируются и затем показываются существующим
Canvas-плеером. После конца пул повторяется; новых repair нет. Повторная порция
с тем же seed/ordinal не увеличивает ранг системы. При небольшом пуле некоторые
блоки могут оставаться невосстановленными даже без дальнейших потерь. Это не
бесконечный fountain и не гарантия восстановления из любых K символов.

В QRM1 формат матрицы прежний. В конфигурацию плеера добавлены `transport="lt"`
и `data_frames` для числа source+repair; это число отлично от числа исходных
чанков вложенного descriptor. Число матриц сверяется с QRM1 и CRC файла.
Лимит LT — 128 МиБ матриц, автономного HTML — 8 МиБ до Base64. Приём данных
из Python в браузер не содержит никакой обратной связи от хоста.

## Состояние и ограничения ресурсов

`FecSession` использует `fec.sqlite3`, user_version=1, таблицу
`packets(kind,idx,raw,PRIMARY KEY(kind,idx))`. Байты и ключ коммитятся вместе с
`synchronous=FULL`; COMMIT предшествует публикации восстановленного блока.
Блокировки ОС и политика одного писателя — как в И04.

- До bootstrap: максимум 64 пакета/4 ID/30 с; буфер не сохраняется после аварии.
- Максимум 256 блоков и 3K repair на блок, каждый пакет проверяется до backend.
- В RAM максимум 8 графов; при вытеснении граф воспроизводится из SQLite.
- Журнал ограничен рассчитанным конечным пулом, входная БД ≤160 МиБ; длины BLOB
  проверяются до загрузки в Python. Повторы не увеличивают журнал.
- Перед стартом проверяется место на символы, блоки и сборку плюс 16 МиБ резерва;
  перед каждой записью проверка повторяется. Это не резервирование диска.
- `blocks/*.bin` сохраняются после fsync/rename. После перезапуска символы
  перепроверяются, блоки воспроизводятся по одному; старый кэш не считается
  доказательством корректности. `resume_seconds` включает эту работу.

Прогресс: уникальные принятые/зафиксированные символы и восстановленные блоки.
`missing_ranges=null`: точное число недостающих независимых символов неизвестно.
Полезные байты увеличиваются только после восстановления блока, поэтому скорость
может изменяться скачками. Окончательный успех — только SHA-256 всего объекта.

Совместимость подтверждается векторами и тестами Python 3.10/3.12 на Windows.
Другие LT-библиотеки, RaptorQ и Wirehair не совместимы с этим профилем автоматически.
