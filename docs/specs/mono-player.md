# mono-safe: браузерный транспорт И03

## Разделение компонентов

`pack` И02 создаёт неизменяемый зашифрованный архив и технический дескриптор.
`render` проверяет размер/SHA этого объекта, присваивает новый случайный transfer ID
и заранее генерирует QR из AQR2. Браузер не получает пароль, исходные имена или
открытые файлы. Код и данные поставляются локально, без CDN и browser file picker.
Дополнительные пакеты импортируются только при использовании соответствующего
адаптера. Python не участвует в переключении готовых кадров.

## Контрольный профиль

| Параметр | Значение |
| --- | --- |
| Протокол | AQR2-repeat v1, только `7z-aes256` |
| QR | V40-L, byte mode, автоматический mask |
| Полезные байты data | 2800 по умолчанию в дескрипторе; предел 2909 |
| Матрица | 177×177; белая тихая зона по 4 модуля, итого 185×185 |
| Длительность кадра | 600 мс по умолчанию; 50…10 000 в плеере |
| Metadata | В начале цикла и после каждых 8 data; параметр `--metadata-every` |
| Масштаб | Целое число backing pixels на модуль, сглаживание выключено |
| Верхний отступ | 48 CSS px только в fullscreen, настраивается до 128 |

Для N чанков и периода M в цикле `N + 1 + floor(N/M)` кадров. Metadata хранится
один раз; расписание ссылается на неё. При подключении посреди цикла до metadata
действуют ограниченный буфер И01 и последующие повторения. Обратного канала нет.

Генератор по умолчанию — Segno 1.6.6; qrcode остаётся альтернативой. Для Segno
явно заданы byte mode, version=40, error=L, micro=False, boost_error=False, чтобы
автоматическое повышение ECC не меняло профиль. [API Segno](https://segno.readthedocs.io/en/stable/api.html).
Выбор по локальному сравнению и результаты бинарного round-trip приведены в отчёте.

## Формат матриц QRM1

`frames.bin` — формат представления плеера, не новый транспортный протокол.

| Offset | Размер | Значение |
| --- | ---: | --- |
| 0 | 4 | ASCII `QRM1` |
| 4 | 2 | Big endian, 177 |
| 6 | 2 | Big endian, 4 — тихая зона |
| 8 | 4 | Big endian, число уникальных матриц N+1 |
| 12 | … | Матрицы: по 3917 байт каждая |

Матрица 0 — metadata, матрицы 1…N — data с индексами 0…N−1. Модули матрицы
идут построчно, старшим битом вперёд; 1 означает чёрный. Неиспользуемые биты
последнего байта нулевые. Тихая зона не хранится, браузер рисует её белой.

HTML содержит технический config со схемой, дескриптором, transfer ID, точной
длиной файла матриц и CRC32. Браузер проверяет длину, CRC и заголовок до ready.
Это обнаружение повреждения комплекта, не аутентификация страницы.

Внешний комплект: `index.html`, `player.js`, `frames.bin`. Автономный
`standalone.html` содержит тот же JS и Base64 матриц. В JupyterLab для fullscreen
используется отдельное открытие через подтверждённый маршрут И00, не iframe
вкладки просмотрщика.

## Память и предварительная генерация

На кадр нужно 3917 байт, независимо от размера показа. Python обрабатывает
пакеты/матрицы последовательно, пишет бинарный файл и потоково формирует Base64;
все PNG/изображения в памяти и DOM не создаются. В браузере хранится один массив
матриц, короткое расписание индексов и текущая отрисовка, без массива PNG.

Лимит decoded matrices — **32 МиБ** для внешнего комплекта и **8 МиБ** для
автономного. `render --estimate` проверяет расчёт до генерации. Например, около
1 МиБ зашифрованного объекта требует около 1,5 МиБ матриц и 2 МиБ Base64.
Ограничение автономного файла связано с промежуточными строками HTML/Base64;
внешний fetch заполняет заранее ограниченный буфер и отказывает при превышении.

Большие объекты не подкачиваются частями в этой итерации: весь разрешённый массив
загружается до запуска. Эти лимиты относятся к представлению; предел контейнера
64 МиБ не означает, что любой такой объект поместится в плеер И03.

## Отрисовка и управление

Сторона Canvas равна `185 * floor(min(доступная_ширина, доступная_высота)/185)`
в backing pixels. CSS-размер делится на DPR; центрирование привязывается к сетке
backing pixels. При Full HD/DPR=1 в fullscreen с отступом 48 получается QR 925×925,
по 5 px на модуль. Фактический масштаб VDI/хоста этим не измеряется.

Отдельный Canvas 185×185 получает целочисленную матрицу с тихой зоной, затем
масштабируется nearest-neighbor в видимый Canvas. Кнопки/статистика находятся вне
области QR. Если места нет даже для 1 px на модуль, показ недоступен; при малом
масштабе плеер предлагает увеличить область.

Показ работает через requestAnimationFrame/performance.now. После задержки
показывается один следующий кадр с полным интервалом удержания; пачки пропущенных
кадров нет. Пауза не меняет текущий рисунок. Скрытая вкладка приостанавливает показ
до ручного Старт. При pagehide отменяются callback/fetch и освобождаются ссылки.

Отчёт плеера schema=1 содержит заданный интервал, число обновлений, активное время,
фактическую частоту вызовов отрисовки, последние интервалы, загрузку и геометрию.
Смена скорости не обнуляет среднее: для отдельного замера нажмите «С начала».
Отчёт не содержит URL/query-токенов и не доказывает доставку кадров на хост.

## Приём

`mss` снимает выбранный монитор, ZXing читает один QR, парсер И01 проверяет пакет.
Дубликаты не увеличивают ни полезные байты, ни таймер прогресса. После сверки
архива захват завершается; `--extract-to` передаёт его модулю И02 и запрашивает
пароль. Ошибка пароля не уничтожает объект. Состояние транспорта и результат
распаковки хранятся отдельно.

Общий timeout по умолчанию отключён. Первый поток ожидается 120 с, отсутствие
новых данных — 600 с. Эти ограничения независимы. Средняя полезная скорость
считает только уникальные байты, включая время ожидания с начала приёма;
фактическая частота захвата включает стоимость декодирования.

Запись скриншотов и аппаратных ID мониторов в отчёт не производится. Сам захват
не определяет, открыт ли локальный плеер или VDI: реальный маршрут фиксируется в
протоколе эксперимента. ROI, multi-QR и resume живого захвата — И04.
