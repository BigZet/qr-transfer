# Порционный плеер, версия 0.6.2

Транспорт AQR2-repeat/LT и QR-матрицы QRM1 не меняются. Контейнер и состояние
приёмника прежние. Для большого repeat действует предел архива 64 МиБ;
для LT сохраняются 16 МиБ и 256 блоков. Это не расширение LT wire format.

## Файлы

Генератор сохраняет `frames.bin` (полный QRM1) и разбивает матрицы без 12-байтного
заголовка на `parts-<32 hex>/<шесть цифр>.bin`. Порция содержит 8..1024 матриц по
3917 байт, по умолчанию 256. Последняя может быть короче. Дисковая копия полного
набора остаётся для refresh/standalone: объём матриц на диске примерно удваивается.
Без `--live` генерация завершается целиком перед публикацией HTML.

В config появляется `parts`: schema=1, directory, frames_per_part, items.
Каждый item содержит bytes и CRC32 всего файла. Число порций/размер последней
сверяются с data_frames+1 и matrix_bytes. Пути ограничены фиксированным шаблоном,
порции не могут перенаправлять запросы на произвольные URL. Верхний суммарный
бюджет матриц для порционного плеера — 256 МиБ; в браузер целиком он не выделяется.

Новый `index.html` содержит JS и manifest, загружает порции обычными GET с
`cache:no-store`, без Range-заголовков. Серверу достаточно выдавать статические
файлы. `standalone.html` использует прежние встроенные данные и предел 8 МиБ.
Плеер сохраняет чтение старого единого внешнего frames.bin при отсутствии parts.

## Буфер и показ

### Показ во время генерации

`render --live --external-only` публикует index после первой готовой порции.
Матрицы вычисляются на Python, параллельно в ограниченном пуле процессов;
порядок пакетов сохраняется. CLI `--workers 0` выбирает до четырёх процессов
с учётом доступных CPU и квот в стандартных путях cgroup. Явно разрешены 1..16.
Программный API по умолчанию использует один процесс. Очередь — до 2 × workers.

В раннем manifest `parts.live=true`; CRC будущих порций равен null. Для каждой
порции сначала атомарно публикуется BIN, затем `<шесть цифр>.json` с bytes/CRC32.
Плеер читает этот дескриптор перед BIN и проверяет размер и CRC как обычно.
`generation.json` (schema=1) содержит state=running/complete/failed,
generated_frames и total_frames. После завершения index заменяется полным
manifest с известными CRC и live=false. Уже открытая вкладка продолжает работу.

Пока дескриптор отсутствует (404), опрос повторяется раз в секунду: текущий QR
сохраняется, показывается ожидание генерации. Лимит ожидания порции — 10 минут,
после ошибки доступен повтор через Старт. Управляющие JSON ограничены 4096 байт.
При state=failed показ останавливается с объяснением. При state=complete
дескриптор запрашивается ещё раз для устранения гонки публикации. Принудительное
убийство Python может оставить running до таймаута. Возобновления генерации нет.
На Windows атомарная замена повторяется до двух секунд при временной блокировке
читателем. Standalone требует полной подготовки и несовместим с --live.

### Загрузка готовых матриц

- До готовности читаются metadata и порции начальных позиций; остальные по мере
  необходимости, с опережением на следующий показ.
- Не более 4 готовых порций и 1 загружаемой, загрузки последовательные. Metadata
  копируется отдельно в 3917 байт, чтобы не перечитывать первую порцию на каждой
  служебной позиции. Потребность в матрицах не растёт с размером архива или циклом.
- Верхняя граница учтённых бинарных буферов: `5 * part_frames * 3917 + 3917`.
  Это не RSS вкладки: Canvas, расписание индексов, сетевые буферы и память браузера
  считаются отдельно. Маленькое расписание ссылок и manifest остаются в памяти.
- Текущие тайлы защищены от вытеснения. Кадр обновляется только когда все его
  слои/слоты доступны. Если следующая порция задерживается, курсор не продвигается,
  на экране остаётся прежний QR; после готовности выдерживается полный интервал.
- Размер и CRC проверяются до допуска порции к показу. При ошибке воспроизведение
  останавливается; Старт повторяет загрузку. Для ошибки первоначальной загрузки
  требуется обновление страницы. Нет автоматического пропуска испорченной порции.
- Таймаут отсутствия сетевых данных 60 с; он обновляется на каждом блоке ответа.
  Закрытие страницы отменяет активный запрос. Новый цикл перечитывает вытесненные
  порции. Пауза, ручной шаг, изменение цвета/слотов не меняют transfer ID.

## Оценка времени

Номинальный полный цикл: `число тайлов * interval_ms / (1000 * slots)`.
Расписание учитывает metadata, visual bootstrap и padding. Для staggered каждый
шаг меняет один слот и имеет период interval_ms/slots. После трёх измеренных
интервалов оценка использует средний фактический период, не меньше заданного.
Паузы не считаются, смена темпа/раскладки сбрасывает прежние интервалы.

Остаток относится к концу текущего цикла, а не к подтверждённому завершению
приёмника. У отправителя нет ACK: repeat может потребовать несколько циклов,
LT может завершиться раньше полного пула. Плеер не останавливается по таймеру.
Оценка видна в обычном и полноэкранном режиме; под неё резервируется нижняя полоса,
не перекрывающая QR/цветовые образцы при целевой геометрии Full HD.

## Обновление старого плеера

`tools/refresh_player.py DIRECTORY --paged --part-frames 256` проверяет размер и
CRC frames.bin, создаёт новую папку порций, сохраняет резервную копию index и
атомарно заменяет index. Архив/ID/матрицы неизменны. Старые папки не удаляются:
открытые страницы могут ещё использовать старый manifest. После ошибки подготовки
могут остаться неиспользуемые порции; HTML на них не ссылается.
