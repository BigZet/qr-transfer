# RGB QR planes v1

Статус: экспериментальная визуальная оболочка AQR2, независимая от repeat/LT и
7z-контейнера. Пакеты и SQLite остаются совместимыми с И04/И05.

## Плоскости и палитра

Все матрицы — QR V40-L, 177×177 модулей, quiet zone 4. Разные маски допускаются,
размер фиксирован также для metadata и служебного QR. Бит 1 означает тёмный модуль.
Канал соответствующей плоскости равен 0 для тёмного, 255 для светлого модуля.

| Профиль | Слои | Значение RGB для индекса i |
| --- | --- | --- |
| `rg4` (семейство `rgb-planes-v1`) | R, G | R=255*(1-(i&1)), G=255*(1-((i>>1)&1)), B=255 |
| `rgb8` (то же семейство) | R, G, B | каждый канал 255*(1-бит i), порядок битов R/G/B |

Порядок 8 цветов: белый, cyan, magenta, синий, жёлтый, зелёный, красный, чёрный.
Четыре цвета — первые четыре. В QR каждого слоя лежит отдельный бинарный пакет.
Служебные и транспортные metadata-кадры одинаковы во всех слоях, рисуются
чёрно-белыми. Последняя неполная группа дополняется валидными metadata-пакетами.

## Геометрия и bootstrap

Цветной тайл занимает **185×195 модулей**, QR с quiet zone — верхние 185×185.
Образец i занимает x=[4+22i,22+22i), y=[187,193), координаты от начала тайла.
Это вне QR и тихой зоны. Зазор между двумя тайлами — 8 физических Canvas-пикселей.
Масштаб целочисленный; при недостаточном размере двух QR плеер выбирает один,
как в И04. Верхний отступ fullscreen применяется к области целиком.

В config HTML включена отдельная packed-матрица служебного QR, 3917 байт
(5224 символа Base64 сверх frames.bin). Его raw payload — `QRC1` и фиксированный
JSON: family, допустимые profiles, версия QR/ECC, quiet, tile, patches, order и
полярность dark. Точные байты — `qr_transfer.rgb.SERVICE`.
Он не содержит пароль, имена или данные файла. Декодер признаёт только точную
версию SERVICE и не передаёт её в AQR2-приёмник. Цвет выбирается оператором на
обеих сторонах; bootstrap описывает семейство и не переключает приёмник.

В цветном расписании сначала service, затем metadata; после каждых
`metadata_every` пакетов повторяются metadata и service. Каждая из этих записей
занимает целый тайл. Данные между ними группируются по 2/3; неполная группа
дополняется metadata. Для двух слотов число тайлов дополняется до чётного.
Python `rgb.schedule` и JS формируют одинаковое расписание. Матрицы пакетов в
QRM1 прежние, в памяти браузера цветные кадры целиком не накапливаются.

## Приём и калибровка

Начальный поиск: QR по пороговым изображениям R/G/B (только R/G для rg4).
Периодический чёрно-белый service позволяет найти координаты, даже когда
смешанные цветные данные не проходят пороговый декодер. Распознаются максимум
два прямых тайла; поворот/перспектива не поддерживаются.

После определения QR-границ выбирается центральный пиксель каждого модуля.
Для `palette` из явных образцов берутся медианные RGB-центры. Если полоска
обрезана или минимальное расстояние между центрами меньше 60 в шкале RGB 0–255,
тайл пропускается; старая калибровка не используется. Иначе каждый модуль относится
к ближайшему центру по евклидовому RGB-расстоянию, индекс центра даёт логические
биты. Это простая модель, не компенсация произвольной субдискретизации цвета VDI.

Контрольный `threshold` сравнивает каждый центральный канал с 128. В обоих
случаях восстанавливается чёрно-белый QR с quiet zone, затем работает zxing-cpp.
Слои независимы. Только AQR2 CRC, ID и проверки контейнера определяют прогресс.
Проверка SHA-256 всего архива обязательна до распаковки.

Центры считываются заново на каждом снимке. Размер изображения сбрасывает
геометрию немедленно; полный поиск повторяется не реже раза в секунду обработки.
При изменении цвета внутри того же размера используются текущие образцы.
`--no-cache` ищет геометрию на каждом кадре. Неизменённые слои можно пропускать
по BLAKE2s бинарной матрицы; кэш не превышает 2×3 записей и периодически сбрасывается.
По умолчанию эта оптимизация выключена. Очередь захвата — прежние 1/2 снимка,
параллельных декодеров нет. NumPy работает с одним снимком и одним тайлом за раз.

## Пределы

Реальный цветовой профиль VDI/Э01 пока не измерен. Большие калибровочные поля
не доказывают сохранность мелких цветных модулей. Протокол не обещает 3× скорости:
service, padding, QR ECC, пропуски и стоимость трёх/шести декодирований входят
в фактическое время. Перестановка пакетов между слоями по циклам пока не выполняется:
постоянно потерянный слой может блокировать repeat; LT помогает в пределах пула.
