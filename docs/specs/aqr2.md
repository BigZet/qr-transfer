# AQR2-repeat v1: нормативный формат И01

Статус: реализован. Все целые поля — unsigned, big endian. Пакет занимает не более
2953 байт и содержит ровно один заголовок и payload. Это транспорт подготовленного
объекта; CRC/SHA-256 проверяют целостность, но не подлинность и не наличие шифрования.

## Заголовок: 44 байта

| Offset | Байты | Поле | Правило |
| --- | ---: | --- | --- |
| 0 | 4 | magic | ASCII `AQR2` |
| 4 | 1 | kind | 0 metadata, 1 data; 2 зарезервирован для FEC |
| 5 | 1 | flags | Только 0 |
| 6 | 2 | header_length | Только 44 |
| 8 | 2 | profile | 1 repeat; 2 зарезервирован для будущего FEC |
| 10 | 2 | descriptor_version | Только 1 |
| 12 | 16 | transfer_id | Случайные 128 бит для каждой пакетизации, `os.urandom(16)` |
| 28 | 4 | index | Data: 0…total−1; metadata: 0 |
| 32 | 4 | total | 1…2³²−1, количество уникальных чанков данных |
| 36 | 4 | payload_length | Точный размер остатка пакета |
| 40 | 4 | crc32 | CRC32 всего пакета, при расчёте байты 40…43 заменены нулями |
| 44 | N | payload | Бинарные данные, не строка |

CRC соответствует `zlib.crc32(header_with_zero_crc + payload) & 0xffffffff`.
Лишние байты, усечённый пакет и пустой data payload отклоняются. Проверка длины и
CRC предшествует выбору сессии. Неизвестные типы, flags, версии, профиль и длина
заголовка отклоняются. Никакие расширения не интерпретируются эвристически.
FEC получит отдельный профиль: параметры блока/символа будут определены И05 в
его собственном заголовке/дескрипторе; repeat v1 не меняет смысл полей.

## Метаданные

Один пакет, максимум 1024 байта payload, без фрагментации. UTF-8 JSON object:

```json
{"chunk_size":2800,"container":"opaque-test","descriptor_version":1,"object_size":65536,"sha256":"b534aa85a81fcc6e37ba848aa55becb54b49639dac24b0d7ebc687419eb52eba","total":24,"transport":"aqr2-repeat"}
```

Все семь полей обязательны, неизвестные и повторные ключи запрещены. Числа —
целые JSON integers (не bool/float). SHA-256 — 64 строчных hex-символа.
`container`: `opaque-test` для тестового объекта или `7z-aes256` для адаптера И02.
Последнее значение — декларация типа, а не доказательство шифрования; ядро не
распознаёт архив и не принимает пароль. CLI И01 создаёт только `opaque-test`.
Исходные имена, пути, пароль и ключи в дескриптор не входят.

Encoder пишет ASCII JSON с сортировкой ключей и без пробелов. Decoder допускает
другой порядок/пробелы; повторы metadata сравниваются по значению дескриптора.
`total` в заголовке и дескрипторе обязан совпасть.

`object_size > 0`; `total = ceil(object_size / chunk_size)`.
Все чанки, кроме последнего, ровно `chunk_size` байт. Последний имеет длину
`object_size - (total - 1) * chunk_size`. Пустой transport object запрещён;
пустой исходный файл в И02 представлен непустым контейнером.

## Вместимость и циклы

Для V40-L byte mode: 2953 байта QR − 44 байта заголовка = **2909 байт data payload**.
Значение по умолчанию 2800 оставляет запас. QR-адаптер явно использует byte mode;
тест кодирует/декодирует пакет предельной длины 2953 байта с бинарными значениями.
Для другой версии/ECC лимит необходимо пересчитать отдельно.

Каждый цикл начинается metadata, затем идёт data по индексам. После каждых
восьми data снова metadata. Число циклов задаётся до запуска; сообщения приёмника
не влияют на отправителя. Так возможны позднее подключение и добор пропусков.
Новая пакетизация получает новый ID даже для того же объекта. Возобновление
использует прежний поток/ID.

## Приём, квоты и конфликты

- По умолчанию объект ≤64 МиБ, total ≤65 536. Wire format допускает больше;
  локальная квота строже. Это начальные консервативные лимиты, не замер предела VDI.
- До metadata: ≤64 пакетов суммарно (не более 188 992 байт сырых пакетов), ≤4 ID,
  TTL 30 секунд по монотонным часам. Просроченные кандидаты удаляются при обработке
  следующих пакетов. Неизвестные/повреждённые пакеты не расходуют эту квоту.
- Первые валидные metadata фиксируют активный ID и неизменяемый дескриптор.
  Валидные чужие пакеты учитываются как `foreign_session` и игнорируются.
- Одинаковый повтор не увеличивает прогресс. Другие данные того же индекса,
  несовместимое total или metadata дают `conflict`; ранее принятые данные сохраняются.
- Активные чанки хранятся по числовым индексам на диске. В RAM — набор индексов,
  счётчики и ограниченный буфер до metadata. Сборка читает по одному чанку.
- Перед результатом проверяются все индексы, размер и SHA-256. Только затем
  `object.part` переименовывается в `object.bin`. Неполный набор не готов.
- Диск: до двух размеров объекта (чанки + сборка), а с журналом CLI — примерно
  три размера плюс 48 байт на чанк и служебные файлы. Проверка свободного места
  не резервирует его; ошибка записи завершает CLI с ошибкой.

Ограничение 64 МиБ выбрано для первых прогонов на среде с неизвестными свободными
ресурсами контейнера, а не из предположения о доступности всей RAM VDI. Квоты можно
задавать через `Limits` для приёмника; изменение wire profile для этого не нужно.

## Статусы и события

`waiting → buffering → receiving → assembling → verifying → object_verified`.
`buffering` необязателен. `error` и `cancelled` не являются успехом.
`waiting_password → extracting → complete` определены интерфейсом для И02,
но ядро И01 их не выставляет. `content_verified` означает только размер/SHA-256;
`encryption_verified` в И01 всегда false.

`DecodeEvent` schema=1: `reason`, `state`, `received_chunks`, `total_chunks`.
Причины: `format`, `length`, `crc`, `limit`, `unsupported`, `foreign_session`,
`conflict`, `duplicate`, `buffered`, `metadata`, `accepted`, `inactive`.
Счётчики также содержат `expired` и `hash`. События и status не содержат payload.

## Локальный стенд и возобновление

`.aqs` — локальный поток: `AQS1`, затем повторяющиеся uint32 длины и байты пакетов.
Эта обёртка не передаётся через QR. Ридер ограничивает размер до чтения payload;
усечённая запись — ошибка, не конец успешной передачи. CLI читает ≤1 000 000 записей.

В рабочем каталоге `accepted.aqs` содержит только принятые metadata и уникальные
data. `resume` заново проверяет журнал и восстанавливает состояние. Буфер до
metadata не сохраняется. `.lock` исключает одновременную работу двух CLI с одним
каталогом. Журнал после штатной остановки поддерживает возобновление; аварийное
восстановление оборванной записи/устаревшего lock и индексированный resume — И04.
Рабочий каталог локальный, принадлежит приёмнику, не должен редактироваться во
время приёма. `inspect` читает сохранённый status, не проверяет файлы повторно.

## AQR1

Исходные `code.py` и `qr.py` сохранены. `qr_transfer.legacy` отдельно реализует
заголовок `>4sB8sHHHI` и CRC только payload. Автоопределения AQR1 как AQR2 нет.
`inspect-packet --legacy` явно помечает данные как нешифрованный legacy.
API `legacy.assemble` проверяет полный размер/SHA и возвращает байты, игнорирует
filename и ничего не распаковывает; требует metadata прежде data, ограничен
64 МиБ/65 535 чанками и хранит legacy-объект в памяти. Это проверочный адаптер,
а не новый legacy-приёмник с экрана.
