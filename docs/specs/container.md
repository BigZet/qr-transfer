# Парольный контейнер v1 — И02

Реализация: `qr_transfer.container`, backend **py7zr 1.1.3**. Формат транспортного
объекта — обычный 7z: solid LZMA2, AES-256, зашифрованный заголовок. Собственная
криптография не реализуется. Параметры password и header encryption независимы;
при явной цепочке фильтров AES включён отдельным последним фильтром. Это проверяется
не только конфигурацией, но и попыткой открытия без пароля и просмотром coders всех
потоков с паролем. [API py7zr](https://py7zr.readthedocs.io/en/latest/api.html).

В 7z используется вывод ключа из пароля на основе SHA-256; формат поддерживает
AES-256 и solid compression. [Описание формата 7z](https://www.7-zip.org/7z.html).

## Структура

```text
control/manifest.json      служебный манифест, зашифрован
data/<исходное имя>/...    исходный файл либо дерево, зашифровано
```

В архиве записываются сам манифест и точные записи пользовательского дерева;
искусственные записи директорий `control` и `data` не добавляются. Файл пользователя
с именем `manifest.json` находится под `data/` и не заменяет служебную запись.
Одиночный файл, пустой файл и пустой каталог используют тот же процесс.

Манифест — UTF-8 JSON schema=1:

```json
{
  "schema": 1,
  "root": "example",
  "entries": [
    {"path": "example", "type": "directory"},
    {"path": "example/empty", "type": "directory"},
    {"path": "example/a.txt", "type": "file", "size": 0,
     "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"}
  ]
}
```

Неизвестные/повторяющиеся JSON-поля, повторяющиеся пути и отсутствующие родители
отклоняются. Типы — только file/directory. Размеры — неотрицательные integers,
SHA-256 — строчный hex. `root` — один компонент, все записи относятся к этому корню.
Имена и исходные хеши доступны только после расшифровки. Публичный дескриптор
соответствует AQR2, `container=7z-aes256`, размер/хеш относятся к **байтам архива**.
CLI использует нейтральные `object.7z` и `descriptor.json`.

## Профили сжатия

| Профиль | LZMA2 preset | Словарь | Назначение |
| --- | --- | ---: | --- |
| strong | 6 | 16 МиБ | Меньшие расходы памяти/времени |
| max | 9 | 32 МиБ | Сильное сжатие в ограниченном словаре, по умолчанию |
| ultra | 9 + PRESET_EXTREME | 64 МиБ | Явно выбираемый сравнительный профиль |

Точная цепочка: `FILTER_LZMA2(preset, dict_size)` →
`FILTER_CRYPTO_AES256_SHA256`; `header_encryption=True`. Название max не обещает
глобально минимальный архив для любого содержимого. Выбор сделан для ограниченного
бюджета памяти, а не для максимального словаря. Замеры приведены в
[отчёте И02](../reports/container.md). Бюджет реального JupyterHub ещё требуется проверить.

## Подготовка и согласованность

1. Проверить источник, имена и лимиты; ничего не исключать по умолчанию, включая
   `.git`, скрытые файлы и кэши. Ссылки, hard links, Windows reparse points и
   специальные файлы отклонить.
2. Создать приватный временный каталог рядом с будущим архивом. Скопировать туда
   обычные файлы потоком, одновременно вычисляя SHA-256. Манифест описывает эти
   байты; архиватор читает уже подготовленную копию.
3. Сравнить идентичность, тип, число ссылок, размер и mtime исходного файла до/после
   чтения. На Linux учитывается также ctime; на Windows lstat/fstat могут сообщать
   разную семантику ctime, поэтому он исключён из сравнения. После сжатия повторно
   сравнить инвентаризацию всего источника.
4. Проверить размер архива, скрытый заголовок и AES в потоках. Опубликовать архив
   через атомарное создание hard link без перезаписи, затем убрать временную ссылку.
   Файловая система назначения должна поддерживать hard links; скрытого fallback
   с перезаписью нет. Пользовательские hard links в источнике по-прежнему запрещены.

Это не файловый snapshot уровня ОС и не защита от другого процесса, намеренно
меняющего данные и восстанавливающего атрибуты. Для обычных изменений источник
отклоняется; внутренний манифест всегда относится к скопированным байтам.
Выход внутри исходного дерева запрещён. После ошибки/отмены приватные временные
данные удаляются, исходник сохраняется. Гарантированное стирание данных с носителя
не обещается.

## Ввод пароля

CLI использует `getpass`, на подготовке — с подтверждением. Пустой пароль запрещён.
Если терминал не поддерживает скрытый ввод, команда отказывается от чтения вместо
перехода к открытому вводу. Пароля нет в аргументах, environment-настройках,
дескрипторе, session status и JSON-отчётах. Неизвестные аргументы CLI не отражаются
в тексте ошибки, чтобы не выводить случайно переданный пароль.

API получает Python-строку лишь на время операции; гарантированное стирание строки
из RAM не обещается. Backend exception text не показывается: ошибка открытия
возвращает `password_or_damaged_container`, поскольку причины не всегда различимы.
После отказа зашифрованный архив остаётся для повторной попытки.

## Проверки и публикация распаковки

До ввода пароля CLI проверяет размер и SHA-256 по принятому дескриптору. API также
повторяет проверку перед распаковкой. После пароля проверяются шифрование потоков,
кодеки (только AES/LZMA2), словарь LZMA2 ≤64 МиБ и список записей.

Пути обязаны быть относительными с `/`. Запрещены пустые компоненты, `.`/`..`,
абсолютные пути, обратная косая черта, drive/UNC, ADS (`:`), недопустимые Windows
символы/имена устройств, завершающие точки/пробелы, управляющие символы и surrogate.
До записи проверяются дубликаты и коллизии `NFC + casefold`, включая родителей.
Никаких переименований «для удобства» нет: несовместимое дерево даёт ошибку.

Backend извлекает файлы через `WriterFactory`/`Py7zIO`. Наш обработчик создаёт
**числовые spool-файлы**, не использует архивные имена как файловые пути и проверяет
каждую запись до её выполнения. После извлечения проверяются точное множество
файлов/директорий, размеры и SHA-256 по манифесту. Затем в приватном каталоге
собирается дерево с проверенными именами. Только оно публикуется под новым именем:
Windows `rename`, Linux `renameat2(RENAME_NOREPLACE)`. Существующее имя не заменяется.
На иной ОС или неподдерживаемой файловой системе операция завершается ошибкой.

Результат: новый каталог, внутри которого исходный файл/корневое дерево под своим
именем. Гарантии: имена, байты файлов, вложенность и пустые каталоги. Права, ACL,
владельцы, исходные timestamps, ADS и прочие метаданные ОС не восстанавливаются.

## Лимиты по умолчанию

| Ресурс | Лимит |
| --- | ---: |
| Зашифрованный объект | 64 МиБ, согласовано с И01 |
| Сумма байтов пользовательских файлов | 256 МиБ |
| Записи дерева, включая директории | 10 000 |
| Манифест | 2 МиБ |
| Путь | 1024 байта UTF-8; глубина ≤64; компонент ≤255 UTF-16 units |
| Запас свободного диска | 16 МиБ |

Проверяются как заявленные, так и фактически записанные размеры; короткая запись
тоже не проходит сверку. Подготовке нужно место под snapshot и архив. Распаковка
перемещает spool-файлы внутри одной файловой системы, без второй полной копии.
Свободное место проверяется до старта и перед каждой записью; это не резервирование
диска. `ContainerLimits` позволяет задавать меньшие квоты в API.

Лимиты записи не являются общим лимитом RAM/CPU процесса: библиотека разбирает и
декодирует заголовок до того, как доступны все наши проверки, и выделяет свои буферы.
Тесты повреждённых архивов не доказывают безопасность любого злонамеренного файла.
CRC, внутренний SHA-256 и публичный транспортный SHA-256 обнаруживают ошибки, но
не аутентифицируют отправителя. Обычный парольный 7z здесь не объявляется AEAD.

## Состояния

Транспорт сохраняет `object_verified`. Распаковка — отдельная операция: проверка
объекта → скрытый пароль → временное извлечение → сверка → `complete` в результате
CLI. При неправильном пароле повторяется только распаковка, экран не нужен.
Session status И01 не меняется на complete: это состояние транспорта, а не парольной
операции. `inspect-container` подтверждает транспортный хеш и скрытый заголовок;
без пароля он не заявляет проверку шифрования payload.
