# И02: локальные результаты

Дата: 15 сентября 2026. **Реализация и локальные проверки готовы.** Интеграционная
приёмка на Linux/JupyterHub остаётся открытой: внутреннее зеркало, скрытый ввод и
реальный бюджет памяти ещё не проверены. WSL на текущем хосте отсутствует; успешное
выполнение Linux-тестов не заявляется.

## Backend и совместимость

- py7zr **1.1.3**, LZMA2 + явный AES-256 filter, шифрование заголовка.
- Windows, Python **3.10.21 и 3.12.10**: по **52/52 теста** всего, из них 22 — И02.
- Скрытый ввод с подтверждением проверен реальным вызовом `pack` в Windows PTY:
  введённый синтетический пароль не появился в выводе. JupyterHub terminal ещё
  требует такого же smoke-теста.
- Все закреплённые зависимости скачаны как готовые wheels для Linux x86_64,
  CPython 3.10, manylinux 2.17/2.28 из публичного PyPI. Это проверка доступности
  поставок, а не запуск на Linux и не проверка корпоративного зеркала.
- Системный `7z` не используется как backend. Пароль не передаётся подпроцессу
  архиватора через argv; компрессия/распаковка идут внутри Python.

## Корректность

Проверены пустые/маленькие/бинарные/сжатые файлы, пустое и вложенное дерево,
Unicode/emoji, скрытые файлы и отдельное пространство имён служебного манифеста.
Ссылки и специальные исходники отклоняются. Изменение источника во время упаковки
и отмена не публикуют архив, временные копии удаляются.

Открытие без пароля не раскрывает имена. Неверный пароль не создаёт готового
каталога, повтор с правильным паролем проходит. Проверены полный путь
`pack → AQR2 → receive → unpack`, сохранность исходных байтов и отсутствие пароля
в техническом дескрипторе, состоянии, stdout/stderr. Случайно переданный неизвестным
аргументом CLI пароль также не отражается в ошибке парсера.

Негативные тесты включают повреждение шифротекста (в том числе с пересчитанным
транспортным SHA), манифеста/внутреннего SHA, открытый заголовок или открытый payload,
выход за каталог, абсолютные/Windows-пути, ADS, дубликаты, case/Unicode-коллизии,
архивную ссылку, занятой выход, лимиты числа записей/манифеста/распакованных байтов,
фактические записи сверх лимита и нехватку диска. Повреждение транспорта проверяется
до запроса пароля. Это тестирование перечисленных отказов, не доказательство
безопасности произвольного злонамеренного 7z.

## Сжатие и память

Синтетические данные, локальный диск, один прогон каждого варианта. Время — только
подготовка, RSS — максимум суммы по дереву дочернего процесса за подготовку **и
распаковку**, опрос каждые 10 мс. Общие страницы могут учитываться дважды, короткие
пики могут быть пропущены. Часть замеров шла одновременно с correctness-тестами;
это иллюстрация стоимости профилей, не точный сравнительный бенчмарк CPU/VDI.

| Набор | Исходный размер | strong / max / ultra: размер архива |
| --- | ---: | ---: |
| Текст | 2 400 000 байт | 13 451 / 13 451 / 13 451 |
| Уже сжатые псевдослучайные данные | 2 097 798 байт | 2 098 397 / 2 098 397 / 2 098 397 |
| Каталог с текстом, бинарным и пустыми объектами | 1 862 144 байта | 273 948 / 273 948 / 273 948 |
| Повторяющийся текст | 48 МиБ | 20 492 / 20 492 / 20 508 |

| Профиль, данные 48 МиБ | Подготовка | Пик RSS |
| --- | ---: | ---: |
| strong: preset 6, словарь 16 МиБ | 11,66 с | 225,4 МиБ |
| **max: preset 9, словарь 32 МиБ** | **11,89 с** | **408,6 МиБ** |
| ultra: preset 9 EXTREME, словарь 64 МиБ | 127,39 с | 536,8 МиБ |

На малых наборах подготовка занимала примерно 0,6–0,8 с, RSS 87–124 МиБ.
Кандидат EXTREME со словарём 32 МиБ дал 126,53 с и 20 508 байт на большом тексте;
поэтому стандартный max использует preset 9 **без EXTREME**. Он укладывается в
локальный ориентир 512 МиБ в этом прогоне. Это не верхняя граница RAM для любых
данных/числа файлов и не подтверждённый лимит процесса JupyterHub.

На этих наборах больший словарь не дал выигрыша. Если память/время важнее
потенциального сжатия на других данных, доступен strong. Уже сжатый файл ожидаемо
немного вырос из-за контейнера/манифеста; незашифрованного fallback нет.
