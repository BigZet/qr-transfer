# И06: локальная проверка RGB-QR

16 сентября 2026. Реализованы `rg4` и `rgb8`: две/три QR-плоскости, независимые
пакеты AQR2, repeat/LT, 1/2 тайла, калибровочные образцы и монохромный служебный QR.

## Сквозная проверка

Исходник — 32 768 синтетических бинарных байт; зашифрованный архив — 33244 байт.
Один архив используется для всех комбинаций. Headless Chrome, viewport 1920×1080,
DPR=1, 300 мс на позицию, 5 физических пикселей на модуль, fullscreen с отступом
48 CSS px. Изображения PNG проходят декодер и SQLite, архив проверяется по SHA-256,
затем расшифровывается и сравнивается с исходником. **Все 12 передач точны.**

Время приёма в секундах, один прогон каждой конфигурации:

| Транспорт | QR-тайлы | Моно | 4 цвета | 8 цветов |
| --- | ---: | ---: | ---: | ---: |
| repeat | 1 | 4.187 | 2.922 | 2.610 |
| repeat | 2 | 1.984 | 1.391 | 1.391 |
| lt | 1 | 4.562 | 3.344 | 2.688 |
| lt | 2 | 2.359 | 1.672 | 1.437 |

Это локальные наблюдения, не максимальная скорость VDI и не статистически
устойчивые медианы. Частота снимков зависит от стоимости PNG, QR и SQLite.
Дополнительные service-кадры, metadata и padding учитываются расписанием:
восьмицветная ёмкость не превращается автоматически в 3× полезной скорости.

## Постоянно отсутствующий синий слой

Отдельная проверка пошагово показывает тот же плеер и отбрасывает все декодированные
пакеты B. Это модель полного выпадения слоя, не модель компрессии VDI.

- Repeat после двух циклов (**18 тайлов**) не завершился; ложного успеха нет.
- LT завершился после **13 тайлов**; распакованный файл совпал с исходником.

Тест подтверждает пользу repair в конкретном случае. Конечный LT-пул не обещает
восстановление при любой доле потерь. Пакеты не переставляются между слоями при
повторении цикла, поэтому repeat с постоянно недоступной плоскостью может застрять.

## Работа декодера и ресурсы

При 20 повторениях одного снимка, после начального определения геометрии:

- всегда декодировать: **0,528 / 0,503 с** (repeat/LT);
- пропускать неизменённые успешно прочитанные слои: **0,259 / 0,252 с**.

Опция выключена по умолчанию. В этом микрозамере поиск геометрии отложен на
100 с, чтобы сравнить именно стоимость неизменённых слоёв. В рабочем режиме
поиск раз в секунду сбрасывает кэш. Изменение только одной плоскости проверено
отдельным тестом: изменившийся слой не теряется.

Последняя композиция Canvas в сквозных запусках занимала примерно **0,6–2,4 мс**;
это отдельная выборка, не p95. В JSON сохранены время разделения/калибровки,
попытки и время QR-декодирования по слоям, память процесса и подготовка матриц.
Максимальная выборка RSS приёмника — **88.3 МиБ** (не включает процесс браузера).
В очереди максимум два снимка; геометрий максимум две, отпечатков максимум шесть.
Параллельные декодеры не добавлены.

Палитра перечитывается с каждого снимка, область модуля представлена центральным
пикселем. Вариант `threshold` проверен отдельно от `palette`. Смешение каналов
линейным преобразованием, исчезновение полоски и плохой слой покрыты тестами.
Различимость крупных образцов сама по себе не гарантирует сохранность мелких
модулей после VDI-сжатия.

## Регрессия и упаковка

**89 тестов** прошли на Python 3.10.21 и 3.12.10. Среди новых проверок:
все восемь цветов, точные бинарные payload, 4/8 цветов, плохой CRC одного слоя,
слабая плоскость, неполная передача с resume, поздняя metadata, изменение геометрии,
раздельный кэш плоскостей и расписание с padding.

**24 браузерные проверки геометрии**: DPR 1/1,25/1,8, viewport Full HD → 1280×720 →
4K → Full HD, sync/staggered. Все ожидаемые слои декодированы. Плеер может
автоматически выбрать один тайл при малом размере модулей. Кнопка калибровки и
смена моно/цвета с сохранением ID проверены. Синтетический скриншот доступен локально:
`artifacts/i06/geometry/rgb8-fullhd.png`.

Wheel **0.6.0** установлен на Python 3.10 и проверен вне каталога исходников:
декодированы шесть QR-плоскостей со снимка двух тайлов. На отправителе остаются
Segno и py7zr; NumPy нужен только приёмнику. Linux и внутреннее зеркало PyPI для
новой поставки отдельно не проверялись.

## Исправление загрузки внешнего комплекта

После сообщения пользователя: standalone работает, index зависает и через
`/files/`. Прежний index воспроизвёл зависание при запрете внешнего JavaScript.
Это возможный механизм ошибки, не установленная политика конкретного JupyterHub.
Теперь JavaScript встроен в index, а `frames.bin` остаётся внешним. Добавлены
прогресс, HTTP/размер/CRC-ошибки и таймаут отсутствия данных 60 с на самой странице.

[Локальная проверка](../../benchmarks/rgb-qr/external-loading.json): HTTP с CSP,
запрещающей внешние скрипты и допускающей inline (unsafe-eval разрешён только для
Playwright-проверок). Малый RGB-плеер работает; наборы матриц около 32 и 128 МиБ
готовы за 1,38 и 5,35 с. Крупные наборы содержат повторную валидную матрицу:
это нагрузочная проверка загрузки/CRC/показа, не передача крупных архивов.
При 404, неверном размере и моделируемом таймауте отображается ошибка вместо
бесконечного ожидания. Реальный JupyterHub после изменения ещё нужно проверить.
