# И03: локальные результаты

Дата: 16 сентября 2026. **Реализация готова локально; совместная приёмка
И00–И03 на JupyterHub/VDI остаётся открытой по договорённости.**

[Инструкция запуска](../usage/iteration-03.md) ·
[Машиночитаемые измерения](../../benchmarks/browser-mono/local-2026-09-16.json) ·
[Формат плеера](../specs/mono-player.md)

## Что реализовано

- `render`: зашифрованный объект → упакованные битовые матрицы → автономный HTML
  либо HTML/JS/frames.bin; предварительная оценка размера и длительности цикла.
- Профиль mono-safe: один V40-L, чанки 2800 байт, 600 мс/кадр, повтор metadata
  через каждые 8 чанков. Пароль и открытые имена исходников в плеер не попадают.
- Canvas с целочисленным масштабом, fullscreen, верхним отступом 48 CSS px,
  паузой, шагом, скоростью, остановкой при скрытии вкладки и диагностикой.
- `capture`: mss/ZXing → AQR2 → проверенный архив → скрытый запрос пароля →
  распаковка. Раздельные таймауты, прогресс, журнал и отчёты. Монитор выбирается
  явно; снимки рабочего стола не сохраняются.

## Генератор и подготовка

Измерения Windows/Python 3.12, 8 бинарных пакетов на каждый генератор;
каждый результат декодирован обратно с точным совпадением байтов.

| Генератор | Матрица, среднее | Упаковка матрицы | PNG, среднее | Последний PNG |
| --- | ---: | ---: | ---: | ---: |
| qrcode | 153,52 мс | 2,66 мс | 8,03 мс | 9654 байта |
| Segno | 115,38 мс | 2,64 мс | 7,70 мс | 9588 байт |

По умолчанию выбран Segno 1.6.6. Это небольшой локальный замер, а не универсальный
рейтинг библиотек. Битовая матрица занимает фиксированные **3917 байт**;
повторяемая metadata хранится один раз. PNG в рабочем плеере не используются.
Наблюдавшаяся RSS процессов сравнения — 33–34 МиБ, включая Pillow/ZXing;
это не замер пика отдельного генератора.

Для детерминированного несжимаемого файла **1 048 576 байт**:

- Зашифрованный архив: 1 049 100 байт; упаковка 0,500 с.
- Подготовка 376 уникальных матриц: 44,85 с; frames.bin — 1 472 804 байта.
- Base64 для автономной страницы: 1 963 740 байт плюс HTML/JS.
- Пик RSS Python при генерации, выборка каждые 10 мс: 42,54 МиБ.
- Загрузка: 113 мс для отдельных ресурсов, 161 мс для автономной страницы.
- JS heap: использовано 2,77 МиБ, выделено 5,37 МиБ. Это не полная память Chrome
  и не учёт всех Canvas/GPU/ArrayBuffer.
- Цикл: 422 кадра, расчётные 253,2 с при 600 мс; metadata — 11,14% кадров.
  Расчёт не доказывает пропускную способность VDI.

## Сквозные прогоны

Headless Chrome, viewport **1920×1080**, DPR=1, fullscreen, QR **925×925**,
5 пикселей на модуль с тихой зоной. Отступ 48 CSS px применён.
Каждый прогон начинается после начальной metadata, один кадр дополнительно
пропускается. Декодер читает изображение Canvas; затем ядро собирает архив,
контейнер проверяет манифест, восстановленные байты сравниваются с исходником.

| Прогон | Декодировано кадров | Пошаговый показ/приём | Распаковка | Результат |
| --- | ---: | ---: | ---: | --- |
| 1 | 429 | 46,07 с | 0,198 с | точное совпадение |
| 2 | 429 | 45,87 с | 0,191 с | точное совпадение |
| 3 | 429 | 45,37 с | 0,195 с | точное совпадение |

**Это пошаговые проверки, не измерения передачи при 600 мс и не реальный VDI.**

Отдельно малый каталог с бинарным файлом, Unicode-текстом и пустой директорией
прошёл реальное расписание rAF/600 мс через производственный цикл приёма.
Источник захвата — PNG страницы Chrome: 17 276 байт архива, 53 захвата,
4,453 с, 11,90 захвата/с, 3879,63 новых байта/с. Распаковка и сравнение успешны.
Эта скорость также не характеризует VDI.

## Дополнительные проверки

- 61 тест проходит на Windows/Python **3.10.21 и 3.12.10**: протокол,
  контейнер, ограничения плеера, потери, поздний старт, таймауты, отмена,
  ошибки захвата и продолжительность свыше 300 с без общего лимита.
- Управление: пауза сохраняет пиксели, шаг, повторный Старт, смена скорости,
  задержка JS без ускоренного воспроизведения, reload, скрытие вкладки,
  Space в fullscreen. DPR 1,25 и 1,8 дают целый backing-масштаб и читаемый QR.
- Автономная страница работает с заблокированной сетью. Обрезанные,
  удлинённые и повреждённые данные отклоняются; Старт недоступен.
- При добавлении отрицательных browser-проверок найдено перетирание типа
  события ошибки загрузки; исправлено. Повторный полный набор управления и
  отрицательных проверок на 16 КиБ завершён успешно, `final_controls.ok=true`.
- Установленный wheel версии 0.3.0 на Python 3.10 создаёт автономный плеер
  вне корня исходников; HTML/JS включены в пакет.
- Реальный mss на мониторе 1 проверен без сигнала: таймаут фиксируется как
  неполная передача, ложного успеха нет. Реальная передача QR через mss/VDI
  пока не подтверждена.

## Ограничения и следующий шаг

Плеер предварительно загружает весь набор: максимум 32 МиБ матриц для отдельных
ресурсов, 8 МиБ для автономного варианта (до Base64). Долгая подготовка крупных
объектов остаётся ограничением И03. Лимит контейнера 64 МиБ не означает поддержку
такого размера текущим плеером.

Общий таймаут приёма отключён, ожидание первого потока — 120 с, ожидание новых
чанков — 600 с. Для цикла дольше этого времени увеличьте `--idle-timeout` с запасом,
чтобы дождаться пропущенного чанка. Эти значения не являются оценкой скорости VDI.

Следующий практический шаг — совместная проверка установки Python 3.10 во
внутреннем зеркале, открытия страницы JupyterHub, отступа под панелью VDI,
реального масштаба и трёх передач около 1 МиБ. ROI, несколько QR и возобновление
живого захвата после перезапуска относятся к И04.
