# И07. Браузерный libcimbar и приём со скриншотов

[Общий план](../../IMPLEMENTATION_PLAN.md) · Вход: [И02](02-encrypted-container.md), [И03](03-browser-mono-mvp.md), захват [И04](04-receiver-multiqr.md) · Настройка: [Э01](../experiments/01-vdi-color-channel.md) · Сравнение: [И08](08-performance-profiles.md)

Статус: **запланировано**. Цель — проверить готовый альтернативный визуальный формат на тех же зашифрованных данных и экране. И07 можно выполнять независимо от И05/И06 после подготовки общих интерфейсов; завершённый RGB-кодек не является зависимостью.

## Результат

Закреплённая поставка encoder/decoder, браузерный показ из JupyterHub и адаптер приёма изображений экрана. Либо — воспроизводимый отчёт о техническом препятствии, подтверждённый проверкой доступных путей интеграции. Одного запуска сайта cimbar недостаточно.

## Технологическая отправная точка

Upstream описывает готовый автономный WASM-encoder; готовый upstream WASM-decoder в этом документе не заявлен. Поэтому путь приёма нужно подтвердить отдельно: нативная библиотека/процесс на хосте либо проверенный сторонний порт. Источник: [libcimbar WASM.md](https://github.com/sz3/libcimbar/blob/master/WASM.md).

Контрольный цветной режим — штатный B. В документации производительности указан его четырёхцветный вариант, а старый 8C удалён из-за нестабильности. Восьмицветный RGB из И06 — самостоятельный кандидат. Источник: [libcimbar PERFORMANCE.md](https://github.com/sz3/libcimbar/blob/master/PERFORMANCE.md).

## Задачи

### 1. Ранний тест интеграции

- [ ] Выбрать release/commit upstream и получить полный набор исходников, JS/WASM и сведений о сборке. Не оставлять обязательные ресурсы только ссылками на submodules.
- [ ] Проверить режимы, лимиты размера и точные интерфейсы encoder/decoder именно выбранной версии. Числа из чужого README не заменяют тест границы.
- [ ] Первым делом восстановить небольшой случайный файл из локальных encoder-кадров на целевой ОС хоста. Так проверить самую рискованную часть — пригодный desktop decoder.
- [ ] Сравнить вызов библиотеки и отдельный процесс, способы подачи RGB/RGBA-изображений и возврата событий/байтов. Исключить обязательную камеру/мобильный телефон.
- [ ] Если используется сторонний WASM-decoder, проверить его фактические ресурсы, совместимость потока и возможность связать с capture на хосте. Наличие frontend не доказывает такой интеграции.
- [ ] Проверить происхождение и лицензии включаемых ресурсов, необходимые исходники/сборочные материалы; отразить их в составе поставки.

### 2. Передача общего контейнера

- [ ] Подать в codec уже готовый парольный архив И02 и минимальную оболочку с версией контейнера, точной длиной и SHA-256 зашифрованных байтов.
- [ ] Использовать штатную схему пакетизации/восстановления libcimbar. Не вкладывать AQR2 и дополнительный FEC без доказанной необходимости.
- [ ] Если транспорт повторно сжимает вход, измерить расходы на зашифрованных байтах и проверить возможность отключения без нарушения совместимости.
- [ ] Доставить данные из Python-окружения в browser encoder выбранным маршрутом И00/И03. Не требовать доступа к публичному сайту или выбора файла из недоступной браузеру FS.
- [ ] Связать генерацию с общим плеером: старт, пауза, скорость, fullscreen, остановка и освобождение ресурсов. Для фонового worker проверить ограничения конкретного браузерного маршрута.
- [ ] Проверить реальную геометрию формата в Full HD. Не применять к плиткам cimbar формулу QR quiet zone; не масштабировать готовый формат без round-trip.

### 3. Адаптер приёмника и состояние

- [ ] Передавать снимки/ROI из общего capture-pipeline в нативный декодер без промежуточного видеофайла, если API позволяет.
- [ ] Отделить прогресс штатного FEC от финального получения архива. Успехом общего приложения считать только сверку дескриптора и последующую распаковку.
- [ ] Проверить позднее подключение, пропуск служебной информации, смешанные кадры, паузу и несколько видимых потоков; описать выбор активной сессии.
- [ ] Выбрать способ возобновления: штатная сериализация либо журнал принятых символов/кадров с повторным проигрыванием. Измерить размер журнала и время старта.
- [ ] Если доступны только полные кадры для replay, оценить диск и квоты. Сохранение бесконечного видео не является пригодным возобновлением по умолчанию.
- [ ] После перезапуска codec-процесса не терять подтверждённый общий архив. Ошибки/коды выхода/таймауты адаптировать к общей модели приёмника.

### 4. Размеры и несколько объектов

- [ ] Измерить точный максимальный размер с учётом оболочки, встроенного сжатия и FEC; проверить около границы успешный и отклоняемый вход.
- [ ] Для объекта выше лимита сначала реализовать раннюю понятную ошибку. Если нужный рабочий диапазон выше — добавить явную многочастную оболочку до заявления её поддержки.
- [ ] Для многочастности определить общий object ID, хеш/длину целого, part index/count, размер/хеш каждой части и периодическое расписание передачи всех частей без ACK.
- [ ] Сохранять готовые части независимо и собирать исходные зашифрованные байты только после полной проверки. Перезапуск не требует заново принимать уже готовую часть.
- [ ] Не создавать многочастность только ради формальной поддержки произвольного размера: необходимость определяется реальными входами и лимитом из этой проверки.

## План сравнения

- Один и тот же парольный архив около 1/10/30 МиБ, если допускает проверенный предел; одинаковый Full HD viewport и настройки VDI.
- Сначала static и низкая частота, затем рост частоты до максимума полезной скорости.
- Сравнить с лучшими доступными mono/RGB и их транспортным FEC, включая время подготовки/доставки и native decoder CPU/RAM.
- Выполнить минимум три полные передачи финальных настроек, позднее подключение, потерю серии кадров и перезапуск.
- Проверить 4K отдельно после Full HD; число плиток/символов и частоту записывать в собственных единицах кодека, не в «эквивалентных QR FPS».

## Артефакты реализации

- Поставляемый encoder bundle и desktop adapter либо отчёт о конкретных неуспешных путях интеграции.
- Спецификация общей оболочки, версии и лимита; при необходимости — описание многочастного режима.
- Тестовые кадры, golden round-trip, инструкция воспроизводимой сборки/установки и сравнительный отчёт.

## Проверки и критерии готовности

- [ ] Пройден локальный encoder → desktop decoder с точными байтами и зафиксированными версиями.
- [ ] Полный парольный архив восстанавливается через JupyterHub/браузер/реальный экран Full HD.
- [ ] Позднее подключение, лимит размера и возобновление проверены. Неподдерживаемые возможности отмечены явно.
- [ ] Ресурсы доступны в нашей поставке, дополнительные внешние запросы для передачи не нужны.
- [ ] Есть сопоставимые измерения. Если отсутствует необходимое свойство основного режима, например возобновление, кодек не объявлен основным только из-за быстрого короткого прогона.

После этой итерации кодек получает статус: кандидат в основной, экспериментальный или недоступный в данной среде. Основание — рабочие проверки и ограничения, а не размер исходника или обязательность QR.
