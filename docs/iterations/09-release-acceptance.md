# И09. Поставка, руководство и итоговая приёмка

[Общий план](../../IMPLEMENTATION_PLAN.md) · Вход: [И08](08-performance-profiles.md) и обязательные результаты И00–И07/Э01

Статус: **запланировано**. Цель — превратить проверенную реализацию в полный воспроизводимый комплект для пути GitHub → VDI → JupyterHub и установки приёмника на хосте.

## Результат

Версионированная поставка, инструкции обоих концов, профили с измеренными пределами, автоматические проверки и подписанный результатами чек-лист реального VDI-прогона. Готовность ZIP сама по себе не заменяет финальную передачу из чистой установки.

## Задачи

### 1. Собрать полный комплект

- [ ] Закрепить Python-зависимости и транзитивные ограничения для sender/receiver/дополнительных кодеков. Проверить Python 3.10 как основной и 3.12 как дополнительный.
- [ ] Включить HTML/JS/WASM, конфигурации и профили в устанавливаемый пакет и скачиваемый комплект. Проверить wheel/sdist/release ZIP, а не только запуск из рабочего дерева.
- [ ] Проверить установку из полного ZIP без `.git`, submodule checkout, git-lfs pointers или неописанного скачивания ресурсов во время передачи.
- [ ] Подготовить скрипты сборки сторонних бинарных ресурсов, версии/commit, хеши и сведения об их происхождении. Если сборка нужна, выполнить её на подходящей сборочной машине и включить готовый результат для целевых платформ.
- [ ] Добавить `THIRD_PARTY_NOTICES` и необходимые лицензионные/исходные материалы включённых компонентов, сверив состав с текущим `LICENSE` проекта. Не менять лицензию проекта неявно при заимствовании кода.
- [ ] Не включать пользовательские архивы, пароль, `.env`, состояние рабочих передач и скриншоты рабочего стола. Тестовые образцы синтетические и небольшие.
- [ ] Предусмотреть установку базового режима без дополнительных кодеков. При недоступной зависимости диагностика указывает конкретный компонент и способ установки из предусмотренного источника.

### 2. Руководство пользователя

- [ ] README: назначение, требования, роли `code.py`/`qr.py` или их переходных обёрток, ссылка на quickstart и проверенные профили.
- [ ] Установка отправителя: скачивание нашего проекта на VDI, перенос в JupyterHub, выбор Python 3.10, установка из зеркала, команда проверки среды.
- [ ] Запуск без notebook: путь в Python-окружении, скрытый пароль, подготовка, открытие плеера через проверенный маршрут, полноэкранный/оконный показ.
- [ ] Установка/запуск приёмника: выбор монитора и ROI, каталог состояния/результата, наблюдение прогресса и ручная остановка отправителя после успеха.
- [ ] Возобновление: как найти сессию, перезапустить приёмник, вернуть плеер к тому же архиву/пакетизации и распаковать уже принятый архив отдельно.
- [ ] Профили: когда использовать основной, mono и 4K; что менять при 1080p, смешивании цветов и потере кадров; какие изменения требуют новой транспортной сессии.
- [ ] Ошибки: активный HTML не запускается, WASM запрещён/отсутствует, пакет из зеркала не найден, неверный пароль, мало диска, таймаут, конфликт metadata/состояния, занятое имя результата.
- [ ] Указать лимиты размеров/ресурсов, поддержанные ОС/браузеры и статус экспериментальных кодеков. Не обещать автоматическую адаптацию отправителя по данным хоста.
- [ ] Notebook-пример добавить только как необязательный путь, если он проверен. Основные команды и справка не должны требовать `.ipynb`.

### 3. Автоматические проверки

- [ ] CI: установка и основные проверки Python 3.10/3.12 на заявленных платформах; платформы без проверки не обозначать поддержанными без оговорки.
- [ ] Протокол: golden vectors, binary round-trip, повреждения, границы, конфликтующие пакеты и квоты.
- [ ] Контейнер: пароль/скрытые имена, исходный манифест, безопасные пути, повтор распаковки и отсутствие перезаписи.
- [ ] Состояние: аварийные точки записи, возобновление, повреждения, лимиты диска и один писатель.
- [ ] Browser: загрузка локальных ресурсов, геометрия, управление, остановка, resize, отсутствие утечек таймеров/буферов.
- [ ] Транспорты: выбранные repeat/FEC/RGB/cimbar, позднее подключение, потери, точные конечные байты. Проверки необязательного кодека пропускаются только с явной причиной установки, а не скрыто проходят.
- [ ] Поставка: собрать пакет/ZIP и выполнить quickstart из установленного комплекта в чистом каталоге. Проверить пути к web-assets и запуск вне корня репозитория.

CI с синтетическими снимками не заменяет реальный VDI: этот этап остаётся отдельным подтверждением, привязанным к версии поставки.

## Итоговый сценарий реальной приёмки

1. Получить полный комплект тем же способом, что пользователь: GitHub → VDI → JupyterHub. Начать с новой среды Python 3.10; установить зависимости через доступное зеркало.
2. Подготовить файл и каталог с вложенными/пустыми папками и Unicode, используя скрытый пароль и выбранный сильный профиль сжатия.
3. Открыть плеер проверенным маршрутом, сначала в оконном режиме, затем fullscreen при доступности. Проверить, что содержимое исходного каталога и пароль отсутствуют в передаваемой открытой metadata.
4. На хосте выбрать ROI и принять основной профиль Full HD. Во время большого объекта перезапустить приёмник и закончить через сохранённую сессию.
5. Повторить с поздним подключением, паузой/возвратом видимости и изменением геометрии до Full HD. При необходимости вручную выбрать запасной профиль, соблюдая совместимость пакетизации.
6. Ввести неверный пароль, затем правильный. Повторить распаковку уже принятого архива при занятом имени результата; убедиться в сохранности предыдущего результата.
7. Сверить дерево, размеры и SHA-256 со входным манифестом. Сохранить отчёт о версии, времени, успехах и ограничениях.
8. Подтвердить повторяемость финального набора И08 на точной версии поставки. Если после И08 менялись только упаковка/инструкции, повторить чистую установку и затронутые сквозные проверки; при изменении транспорта/рендера повторить соответствующие измерения.

## Артефакты реализации

- Версионированный устанавливаемый пакет и полный архив поставки с проверкой целостности.
- `docs/usage/`: установка, запуск, возобновление, профили и устранение ошибок.
- Сведения о зависимостях/сторонних компонентах, правила совместимости протокола/состояния и release notes.
- `docs/reports/acceptance.md`: ссылка на конкретный комплект, команды/условия, результаты всех обязательных проверок, открытые ограничения.

## Критерии готовности проекта

- [ ] Чистая установка на целевом JupyterHub под Python 3.10 воспроизводима из полного скачанного комплекта.
- [ ] Основной браузерный путь работает без обязательного notebook и публичных ресурсов во время передачи.
- [ ] Файл и каталог сжимаются, защищаются паролем, передаются, проверяются и восстанавливаются побайтно.
- [ ] Full HD, позднее подключение, потеря кадров, возобновление и изменение геометрии проверены на реальном канале.
- [ ] Пароль/исходные имена не раскрываются в открытых артефактах, ошибочная распаковка не объявляется успехом и не повреждает существующие файлы.
- [ ] Есть основной/запасной профили и честное сравнение FEC, нескольких QR, RGB и libcimbar; статус каждого подтверждён измерениями или проверенной технической причиной.
- [ ] Пройдены обязательные автоматические проверки, реальные испытания и проверка состава поставки; ограничения 3.12/4K/дополнительных ОС описаны.
- [ ] PROJECT.md, README, спецификации, профили и инструкции согласованы с реализованным состоянием; невыполненные экспериментальные возможности не отмечены как готовые.

План считается реализованным после прохождения этих критериев, а не после появления всех названий файлов или успешного короткого локального примера.
