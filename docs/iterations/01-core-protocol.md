# И01. Модульное ядро, протокол и проверочный стенд

[Общий план](../../IMPLEMENTATION_PLAN.md) · Вход: [И00](00-environment-baseline.md) · Далее: [И02](02-encrypted-container.md), [И03](03-browser-mono-mvp.md), [И05](05-erasure-recovery.md)

Статус: **запланировано**. Цель — получить общее ядро, которое проверяется без экрана и не привязано к одному визуальному кодеку.

## Результат

Устанавливаемый Python-пакет, формально описанный AQR2, сохранённая явная совместимость AQR1, интерфейсы контейнера/транспорта/декодера и стенд для повреждений, пропусков и повторов.

## Задачи

### 1. Структура и интерфейсы

- [ ] Создать `pyproject.toml`, пакет `qr_transfer` и минимальные CLI/API. Основная версия Python — 3.10; дополнительные зависимости кодеков не импортируются при запуске базового режима.
- [ ] Выделить из `code.py` генерацию пакета и QR, из `qr.py` — разбор пакета и сборку. Сначала сохранить поведение контрольного режима на тестовых данных.
- [ ] Оставить старые точки входа работоспособными либо сделать явные обёртки; сообщение о legacy-режиме должно соответствовать его отсутствующей парольной защите.
- [ ] Определить `PreparedTransfer`, `TransferDescriptor`, `VisualProfile`, события декодера и интерфейс состояния. Общий результат — проверенный зашифрованный объект на диске.
- [ ] Отделить транспорт QR/RGB, возвращающий пакеты, от файлового транспорта cimbar, возвращающего своё состояние и готовый объект.
- [ ] Выделить команды подготовки, приёма, возобновления и осмотра состояния; конкретный синтаксис зафиксировать в справке. Параметра с открытым паролем в CLI не предусматривать.

### 2. Спецификация AQR2

План задаёт обязательные поля; точные offsets, размер заголовка и сериализация становятся нормативными только вместе со спецификацией и векторами этой итерации.

| Поле/правило | Требование |
| --- | --- |
| Версия и тип | Отдельная сигнатура AQR2; metadata, data, резерв расширений FEC |
| Идентификатор | Случайные 128 бит на экземпляр пакетизации; не производный от исходного имени |
| Индекс и количество | 32-битные беззнаковые значения; выбрать и зафиксировать нумерацию с нуля |
| Длины | Явная длина заголовка/полезной нагрузки, строгая проверка полного размера |
| Профиль | Версия дескриптора и ID транспортного профиля; неизвестный обязательный профиль отклоняется |
| Контроль ошибки | CRC32 заголовка и payload с точно указанным исключением/обнулением поля CRC |
| Метаданные | Размер/хеш зашифрованного объекта, контейнер, chunk size, количество, транспорт; без исходного имени |
| Расширения | Правила чтения flags/неизвестных полей; расширения не меняют смысл старого профиля |

- [ ] Зафиксировать byte order, типы, диапазоны, формулу числа чанков и длину последнего. Нулевой исходный файл поддерживается контейнером; пустой transport object отдельно определить в спецификации.
- [ ] Ограничить метаданные так, чтобы один bootstrap-пакет помещался в базовый QR. Если нужен иной размер, определить фрагментацию с собственной проверкой; не вводить её неявно.
- [ ] Сделать metadata доступной при циклическом позднем подключении. Полные транспортные параметры после принятия неизменяемы.
- [ ] Для FEC зарезервировать отдельный профиль и место для параметров блока/символа. Конкретное отображение на библиотеку фиксируется И05; AQR2-repeat к этому моменту не меняется.
- [ ] Пересчитать допустимый payload по фактическому заголовку, QR-версии и ECC. Не переносить предел AQR1 2930 байт в AQR2 без расчёта.
- [ ] AQR1 читать только как legacy, не пытаться интерпретировать его открытые filename/данные как новый зашифрованный контейнер. Автоматическая распаковка legacy по умолчанию не нужна.

### 3. Состояния и обработка ошибок

- [ ] Состояния: ожидание → ограниченный сбор до metadata → приём → сборка → проверка архива → ожидание пароля → распаковка → готово; отмена/ошибка не равны успеху.
- [ ] Проверять пакет до выбора сессии и выделения больших буферов. Лимитировать число кандидатов до metadata и время их хранения.
- [ ] После согласования фиксировать ID, total, chunk size, длину и хеш. Чужие сессии учитывать отдельно/игнорировать согласно явной политике.
- [ ] Идентичный повтор не увеличивает прогресс. Различный payload того же индекса и конфликтующая metadata дают диагностируемый конфликт, без замены старого значения.
- [ ] Определить квоты архива, пакетов, metadata и RAM; превышение отклоняется до записи/выделения ресурсов.
- [ ] Отделить счётчики причин отказа: формат, длина, CRC, лимит, чужая сессия, конфликт. Логи не содержат raw payload.

### 4. Стенд и тестовые векторы

- [ ] Создать фиксированные бинарные примеры AQR1/AQR2 и ожидаемые разобранные значения. Проверить совместимость на Python 3.10/3.12.
- [ ] Реализовать подачу последовательности пакетов без захвата: перестановка, повтор, случайные и серийные пропуски, порча заголовка и данных, позднее подключение.
- [ ] Генератор тестовых данных задаётся seed; сохранять расписание повреждений для повторного запуска.
- [ ] Отдельный visual round-trip кодирует бинарные значения, включая `0x00`, `0xff` и не-UTF-8, и проверяет возврат точных байтов.
- [ ] Проверить маленькие объекты, границы chunk size, индексы 65 535/65 536 и верхние границы полей без гигантских выделений памяти.
- [ ] Симулятор не создаёт скрытый обратный канал: он подаёт заранее заданную последовательность без подсказки отправителю о потерях.

## Артефакты реализации

- Пакет и точки входа; `docs/specs/aqr2.md`, описание интерфейсов и политики AQR1.
- Тестовые векторы и симулятор в `tests/` и `benchmarks/`.
- Версионированная схема событий измерения; начальные лимиты с обоснованием ресурсами И00.

## Проверки и критерии готовности

- [ ] Пакет устанавливается и базовые команды запускаются на Python 3.10 без дополнительных цветных/FEC-компонентов.
- [ ] Два независимых пути «сериализовать → разобрать» согласуются с фиксированными векторами, а не только друг с другом.
- [ ] Все валидные наборы repeat-пакетов восстанавливаются при перестановке/дубликатах; неполные наборы не помечаются готовыми.
- [ ] Конфликты, порча заголовка, неверная длина и превышение лимитов не создают ложного успеха или неконтролируемого расхода RAM.
- [ ] Legacy AQR1 из текущего прототипа продолжает читаться в выделенном режиме; новая версия не меняет его смысл.
- [ ] Спецификация и реализация совпадают по каждому полю, длине, CRC и граничному случаю.

Следующая итерация может использовать контейнерный интерфейс без зависимости от QR-рендера. FEC и cimbar подключаются к тем же событиям и итоговой проверке, сохраняя собственную внутреннюю схему восстановления.
