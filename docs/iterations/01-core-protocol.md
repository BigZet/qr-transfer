Статус: **реализовано и проверено локально на Windows / Python 3.10.21 и 3.12.10**. [Запуск и границы реализации](../usage/iteration-01.md) · [Спецификация AQR2](../specs/aqr2.md). Цель — получить общее ядро, которое проверяется без экрана и не привязано к одному визуальному кодеку.

Устанавливаемый Python-пакет, формально описанный AQR2, сохранённая явная совместимость AQR1, интерфейсы контейнера/транспорта/декодера и стенд для повреждений, пропусков и повторов.

- [x] Отделить транспорт QR/RGB, возвращающий пакеты, от файлового транспорта cimbar, возвращающего своё состояние и готовый объект.

### 2. Спецификация AQR2

План задаёт обязательные поля; точные offsets, размер заголовка и сериализация становятся нормативными только вместе со спецификацией и векторами этой итерации.

| Поле/правило | Требование |
| --- | --- |
| Версия и тип | Отдельная сигнатура AQR2; metadata, data, резерв расширений FEC |
| Идентификатор | Случайные 128 бит на экземпляр пакетизации; не производный от исходного имени |
| Индекс и количество | 32-битные беззнаковые значения; выбрать и зафиксировать нумерацию с нуля |
| Длины | Явная длина заголовка/полезной нагрузки, строгая проверка полного размера |
| Профиль | Версия дескриптора и ID транспортного профиля; неизвестный обязательный профиль отклоняется |
| Контроль ошибки | CRC32 заголовка и payload с точно указанным исключением/обнулением поля CRC |
| Метаданные | Размер/хеш зашифрованного объекта, контейнер, chunk size, количество, транспорт; без исходного имени |
| Расширения | Правила чтения flags/неизвестных полей; расширения не меняют смысл старого профиля |

- [x] Зафиксировать byte order, типы, диапазоны, формулу числа чанков и длину последнего. Нулевой исходный файл поддерживается контейнером; пустой transport object отдельно определить в спецификации.
- [x] Ограничить метаданные так, чтобы один bootstrap-пакет помещался в базовый QR. Если нужен иной размер, определить фрагментацию с собственной проверкой; не вводить её неявно.
- [x] Сделать metadata доступной при циклическом позднем подключении. Полные транспортные параметры после принятия неизменяемы.
- [x] Для FEC зарезервировать отдельный профиль и место для параметров блока/символа. Конкретное отображение на библиотеку фиксируется И05; AQR2-repeat к этому моменту не меняется.
- [x] Пересчитать допустимый payload по фактическому заголовку, QR-версии и ECC. Не переносить предел AQR1 2930 байт в AQR2 без расчёта.
- [x] AQR1 читать только как legacy, не пытаться интерпретировать его открытые filename/данные как новый зашифрованный контейнер. Автоматическая распаковка legacy по умолчанию не нужна.

### 3. Состояния и обработка ошибок

- [x] Состояния: ожидание → ограниченный сбор до metadata → приём → сборка → проверка архива → ожидание пароля → распаковка → готово; отмена/ошибка не равны успеху.
- [x] Проверять пакет до выбора сессии и выделения больших буферов. Лимитировать число кандидатов до metadata и время их хранения.
- [x] После согласования фиксировать ID, total, chunk size, длину и хеш. Чужие сессии учитывать отдельно/игнорировать согласно явной политике.
- [x] Идентичный повтор не увеличивает прогресс. Различный payload того же индекса и конфликтующая metadata дают диагностируемый конфликт, без замены старого значения.
- [x] Определить квоты архива, пакетов, metadata и RAM; превышение отклоняется до записи/выделения ресурсов.
- [x] Отделить счётчики причин отказа: формат, длина, CRC, лимит, чужая сессия, конфликт. Логи не содержат raw payload.

- [x] Отдельный visual round-trip кодирует бинарные значения, включая `0x00`, `0xff` и не-UTF-8, и проверяет возврат точных байтов.

## Проверки и критерии готовности

- [x] Пакет устанавливается и базовые команды запускаются на Python 3.10 без дополнительных цветных/FEC-компонентов.
- [x] Два независимых пути «сериализовать → разобрать» согласуются с фиксированными векторами, а не только друг с другом.
- [x] Все валидные наборы repeat-пакетов восстанавливаются при перестановке/дубликатах; неполные наборы не помечаются готовыми.
- [x] Конфликты, порча заголовка, неверная длина и превышение лимитов не создают ложного успеха или неконтролируемого расхода RAM.
- [x] Legacy AQR1 из текущего прототипа продолжает читаться в выделенном режиме; новая версия не меняет его смысл.
- [x] Спецификация и реализация совпадают по каждому полю, длине, CRC и граничному случаю.

Следующая итерация может использовать контейнерный интерфейс без зависимости от QR-рендера. FEC и cimbar подключаются к тем же событиям и итоговой проверке, сохраняя собственную внутреннюю схему восстановления.

## Результаты И01

30/30 тестов прошли на Python 3.10.21 и 3.12.10, включая бинарный QR максимальной вместимости. До установки optional QR-зависимостей ядро отдельно прошло в чистом окружении 3.10; visual-тест был явно пропущен. Пакет устанавливается, базовые команды не требуют кодеков.

Синтетический прогон 64 КиБ, пять циклов, seed 42, потери 15%, порча 10%, дубликаты 20%, поздний старт и серия потерь завершился точным SHA-256; повтор сохранённого расписания дал те же счётчики. Это локальный стенд без VDI и без шифрования. Артефакт: [core-2026-09-15.json](../../benchmarks/core/core-2026-09-15.json).

Границы: legacy-функции перенесены в отдельный адаптер с проверкой совпадения байтов, старые точки входа сохранены. Штатное resume переигрывает журнал; устойчивость к аварийному обрыву журнала и быстрый индексированный resume остаются И04. Состояния пароля/распаковки определены интерфейсом, их реализация — И02. Проверка пакета на Linux внутри JupyterHub остаётся частью интеграционной приёмки; локальный Python 3.10 не доказывает доступность зеркала.
