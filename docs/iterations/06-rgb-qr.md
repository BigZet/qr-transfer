# И06. Восьмицветный RGB-QR

[Общий план](../../IMPLEMENTATION_PLAN.md) · Вход: [И03](03-browser-mono-mvp.md), интерфейсы [И04](04-receiver-multiqr.md), [Э01](../experiments/01-vdi-color-channel.md) · Сравнение: [И08](08-performance-profiles.md)

Статус: **запланировано**. Цель — передавать три независимых QR-пакета на площади одного кода и проверить фактический выигрыш восьми цветов.

## Результат

RGB-адаптер отправителя и приёмника, калибровка, отдельные метрики слоёв и профиль для реального VDI. Теоретическая трёхкратная ёмкость сама по себе не считается достигнутой скоростью.

## Входное решение из эксперимента

- Если Э01 подтвердил пригодные 8 цветов при динамических мелких элементах — начать с этой палитры, размера модуля и частоты.
- Если крупные поля различимы, а модули смешиваются — проверить больший модуль, меньшую версию QR и классификацию по соседству/измеренным центрам.
- Если пригодны только 4 цвета — реализовать проверку двух слоёв и оставить восьмицветный профиль экспериментальным с причиной.
- Если цвет в доступной конфигурации не даёт устойчивого канала — закончить локальный RGB round-trip и анализ предела, не объявлять режим пригодным для VDI. Моно и libcimbar продолжают оцениваться по своим результатам.

## Задачи

### 1. Кодирование слоёв

- [ ] Создавать три независимых бинарных QR одинаковой версии и ECC; каждый содержит самостоятельный AQR2-пакет со своим индексом/символом.
- [ ] Зафиксировать соответствие logical bits → RGB/палитра и полярность. В простом RGB-профиле тёмный модуль логического слоя должен восстанавливаться в чёрный QR-модуль после разделения канала.
- [ ] Маски QR могут различаться; finder/timing/quiet zones должны после восстановления каждого слоя оставаться валидными. Матрицы разных размеров не совмещать.
- [ ] Фиксировать версию даже для короткой metadata и последнего чанка. Незаполненные слои последнего кадра заполнять определённым валидным повтором/служебным пакетом.
- [ ] Ввести ID цветового профиля и порядок слоёв, отдельные от контейнера и транспорта. Для 4 цветов использовать явно описанные две логические плоскости, не случайный набор четырёх RGB-значений.
- [ ] Калибровочные цветовые поля размещать вне QR и тихих зон. Монохромный bootstrap описывает профиль/геометрию; он не обязан содержать секретные данные.
- [ ] Поддержать repeat, затем выбранный FEC И05 через тот же пакетный интерфейс. Сам RGB-кодек от готовности FEC не зависит.

### 2. Декодирование и калибровка

- [ ] Использовать ROI/геометрию И04; оценивать положение модулей и брать центральные пиксели/области согласно результатам Э01.
- [ ] Реализовать простой контрольный декодер независимых RGB-порогов и второй путь классификации по измеренным цветовым центрам, если он нужен эксперименту.
- [ ] Классификатор восстанавливает логические биты палитры, из них создаются монохромные изображения слоёв для QR-декодера. Декодер пакетов использует raw bytes.
- [ ] Принимать успешно прочитанный слой независимо от соседних. Смешанный кадр при обновлении не требует отбрасывать корректные пакеты других слоёв/слотов.
- [ ] Вести калибровку по явным служебным образцам, не по предполагаемому содержимому пользовательского файла. Привязать профиль к условиям геометрии/цвета.
- [ ] При изменении масштаба/цвета переобнаруживать геометрию и калибровку. Не заменять её случайными данными кадра.
- [ ] Неуверенное распознавание допускает пробу штатного QR ECC, но байты принимаются только после успешного декодирования и проверки AQR2.

### 3. Производительность и управление

- [ ] Измерить стоимость композиции, калибровки, разделения слоёв и трёх/шести QR-декодирований на снимок.
- [ ] Сравнить декодирование всех слоёв всегда с пропуском неизменённых областей. Оптимизация не должна терять смену одного слоя при неизменных других.
- [ ] Ограничить очередь/буферы и число workers. Запас кадров не растёт с длительностью передачи.
- [ ] Добавить понятный выбор моно/4/8 цветов и калибровку в плеер. Решение о переключении принимается оператором; приёмник лишь показывает рекомендации.
- [ ] При неизменной пакетизации переключение mono/RGB может продолжать ту же передачу; при изменении параметров транспорта создать новую сессию, сохранив возможность вернуться к старой.
- [ ] Измерять полезные байты по каждому слою и общий результат. Особенно проверить ситуацию «два быстрых слоя, один слабый» при repeat и FEC.

## План сравнения

- Одинаковый зашифрованный архив, viewport, QR-версия/ECC и частота обновления каждой позиции: mono → 4 цвета → 8 цветов.
- Затем разрешить каждому режиму собственный лучший модуль/версию/частоту и сравнить оптимальные полные передачи.
- Начать с одного QR, затем 2×1; частоты взять из Э01 и расширять до ухудшения полезной скорости.
- Проверить явное RGB-разделение и измеренную палитру, static и animation, поздний вход, пропущенную калибровку, серийные потери и смену разрешения.
- На 1/10 МиБ выполнить минимум три полных прогона финальных настроек; 30 МиБ и общая финальная матрица — И08.

## Артефакты реализации

- RGB-адаптер и спецификация палитры/слоёв/служебных кадров.
- Профили калибровки с привязкой к условиям Э01 и тестовые скриншоты синтетического содержимого.
- Отчёт по скорости слоёв, общему времени, CPU/RAM и проигрышам/выигрышам относительно mono.

## Проверки и критерии готовности

- [ ] Каждый слой отдельно восстанавливает точные binary payload на локальных изображениях; отдельно проверены все восемь комбинаций модулей.
- [ ] Ошибка одного слоя не блокирует валидные пакеты других, не портит состояние и не создаёт ложный прогресс.
- [ ] Позднее подключение получает bootstrap/калибровку; смена геометрии и перезапуск приёмника совместимы с выбранным профилем.
- [ ] Сквозной архив с паролем восстанавливается на реальном VDI для профиля, заявленного рабочим; все выходные хеши совпадают.
- [ ] Решение о рекомендации опирается на полное время и успехи всех прогонов. При отсутствии выигрыша поддержка остаётся экспериментальной с измеренными условиями, без заявления «3× быстрее».

Измеренный предел восьмицветного режима допустим как результат исследования применимости, но отсутствие реализации/испытания нельзя обозначать как успешную поддержку цвета.
