# И03. Браузерный отправитель и первый полный цикл

[Общий план](../../IMPLEMENTATION_PLAN.md) · Вход: [И01](01-core-protocol.md), [И02](02-encrypted-container.md), браузерный маршрут [И00](00-environment-baseline.md) · Далее: [И04](04-receiver-multiqr.md), [И05](05-erasure-recovery.md)

Статус: **реализована; подтверждены три приёма и распаковки малого каталога на хосте, критерий Full HD/1 МиБ открыт**. Цель — передать парольный архив через один монохромный QR из JupyterHub и получить готовые исходные файлы на хосте.

## Результат

Первый сквозной рабочий сценарий: подготовка → браузер → экран VDI → приём → проверка → пароль → распаковка. Он служит контрольным режимом последующих ускорений; возобновление и несколько QR завершаются в И04.

## Задачи

### 1. Подготовка и доставка в браузер

- [x] Запускать подготовку через CLI/API в окружении JupyterHub, по доступному Python-пути и со скрытым вводом пароля И02.
- [x] Сохранить зашифрованный архив отдельно от представления плеера: смена скорости и повторный запуск не требуют повторной упаковки.
- [x] Реализовать `repeat` с независимыми AQR2-пакетами и периодической metadata; частота metadata — параметр профиля с измеряемыми расходами.
- [x] Сначала сравнить `qrcode` и Segno по бинарным пакетам, времени матрицы, PNG/сериализации и памяти. Выбор генератора не меняет транспорт.
- [x] Начать с заранее подготовленных матриц/кадров и Canvas. Не раздувать одновременно RAM Python, JSON и DOM несколькими копиями всех PNG; оценивать размер перед подготовкой.
- [x] Поддержать полный локальный комплект HTML/JS/данных, открываемый маршрутом И00. Для малого тестового файла допустим автономный HTML; общий формат должен позволять отдельные ресурсы и последующую буферизацию.
- [x] Явно загрузить подготовленные байты из Python-окружения в плеер; не требовать выбора удалённого файла через browser file picker.
- [x] Не использовать CDN. При старте показать загрузку и готовность данных; отсчёт передачи начинается после готовности кадра.

### 2. Геометрия и планирование показа

- [x] Контрольный профиль: один QR, V40-L, чанк 2800 при подтверждённой вместимости AQR2, тихая зона 4 модуля, около 600 мс/кадр. Непомещающийся пакет отклонять до запуска.
- [ ] Вычислять целый масштаб по доступному Canvas. Для V40 с тихой зоной сторона 185 модулей; 5 px дают 925 px. Проверять реальный размер на хосте, а не только CSS.
- [x] Отключить сглаживание при растровом масштабировании, не растягивать матрицу произвольным `vmin`; учесть `devicePixelRatio` и масштаб VDI отдельно.
- [x] Передавать расписание JS и показывать кадры локально в браузере. Python не должен посылать каждый кадр через Jupyter-output.
- [x] Использовать монотонное время, готовый кадр и browser animation callback; при задержке не воспроизводить очередь устаревших кадров ускоренной пачкой.
- [x] Реализовать запуск, паузу, шаг, скорость, fullscreen по нажатию и оконный режим. Состояние/кнопки не перекрывают данные и тихую зону.
- [x] При паузе удерживать последний полный кадр. При перезагрузке/повторном запуске освобождать таймеры, workers и ссылки на изображения.
- [x] При скрытой вкладке или невозможности выдержать частоту показывать фактическое состояние и статистику; не считать заданный FPS достигнутым.

### 3. Сквозной приём

- [x] Подключить текущий захват `mss` к выделенному QR-декодеру и строгому парсеру И01. Проверять входные monitor/fps/timeout, включая нулевые и отрицательные значения.
- [x] Принимать после пропущенного начала, собирать уникальные пакеты и завершать только после согласования metadata и всех данных.
- [x] Сборка выдаёт зашифрованный объект контейнерному модулю. Финальные исходные файлы появляются только после проверки архива и распаковки И02.
- [x] Разделить ожидание первого потока, отсутствие новых данных и общий лимит. По умолчанию общий лимит не должен обрывать обычный большой тест на 300-й секунде; конкретные значения документировать.
- [x] Показывать размер/прогресс/новые байты в секунду, повторы, ошибки, фактическую частоту и текущую стадию.
- [x] Прерывание приёма, неверный пароль и повтор распаковки имеют разные результаты/коды выхода. Полноценное продолжение незавершённой передачи на диске — И04.

## Артефакты реализации

- Плеер и адаптер интеграции с фактическим JupyterHub; API для запуска без notebook.
- Рабочие команды подготовки/показа/приёма и короткий quickstart с реальными путями этой среды.
- Контрольный профиль `mono-safe`, сквозной тест и отчёт о передаче через Full HD.
- Browser-тесты геометрии и управления без зависимости от живого VDI.

## Проверки и критерии готовности

- [ ] На реальном JupyterHub Python 3.10 подготовлены парольные файл и каталог; браузер показывает их без внешних ресурсов.
- [ ] Три передачи тестового объекта около 1 МиБ завершены на Full HD с точным внутренним манифестом. Все попытки и времена записаны.
- [x] Подключение посреди цикла и пропуск metadata завершаются после повторения без обратного канала.
- [x] Неверный пароль исправляется повторным вводом без новой передачи; существующий путь результата не перезаписывается.
- [x] Пауза/шаг/смена скорости/fullscreen/оконный режим и повторное открытие работают. Геометрия не зависит от стандартных 1110 px старого PNG.
- [x] Есть измерения подготовки, доставки в браузер, показа/приёма, распаковки и RAM; ограничения предварительной генерации указаны.

Notebook-встраивание можно добавить как дополнительную оболочку после проверки основного маршрута. Отсутствие `.ipynb` не является дефектом результата.
