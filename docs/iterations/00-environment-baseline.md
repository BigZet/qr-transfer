# И00. Среда JupyterHub и исходный замер

[Общий план](../../IMPLEMENTATION_PLAN.md) · Далее: [И01](01-core-protocol.md) · Независимая ветка: [Э01](../experiments/01-vdi-color-channel.md)

Статус: **запланировано**. Вход: существующий репозиторий, VDI/JupyterHub и хост. Цель — доказать рабочий путь показа и измерить отправную точку до изменения транспорта.

## Результат

Проверенный способ запуска Python и активного HTML в JupyterHub, сведения о зависимостях и ресурсах, воспроизводимая передача тестового файла текущими скриптами. Результат содержит факты о конкретной среде, а не предположения по документации JupyterHub.

## Задачи

### 1. Проверить окружения отдельно

- [ ] Записать ОС/архитектуру JupyterHub, доступный Python 3.10, путь интерпретатора, `pip`, права записи, RAM/диск и лимиты процесса. Python 3.12 проверить отдельно.
- [ ] Определить доступный интерфейс запуска: терминал, Python-консоль либо вызов API из ячейки. Зафиксировать фактический frontend и версии Jupyter-компонентов.
- [ ] Проверить доступ Python к тестовому исходному файлу. Различить каталоги JupyterHub, VDI-рабочего стола и хоста.
- [ ] На хосте проверить ОС, Python, захват выбранного монитора и фактический размер снимка. Записать настройки масштаба ОС, браузера и VDI-клиента.
- [ ] Зафиксировать способ удалённого отображения и настройки цвета/качества, если они видны пользователю. Не выводить тип кодека только по RGB-скриншоту.

### 2. Проверить поставку и зависимости

- [ ] Скачать/перенести полный архив нашего проекта штатным пользовательским путём и проверить структуру после распаковки.
- [ ] Создать отдельную рабочую среду Python 3.10; проверить установку из существующего внутреннего зеркала. Адреса с учётными данными в отчёт не записывать.
- [ ] Проверить основной набор: текущий `qrcode`, Pillow, `mss`, `zxing-cpp`; записать версии, наличие wheels и результаты import/smoke-test.
- [ ] Проверить кандидатов: `py7zr` с транзитивными зависимостями, Segno, NumPy, выбранные по исследованию FEC-пакеты. «Найден пакет» и «работает нужный API» фиксировать раздельно.
- [ ] Если пакет недоступен, записать точную ошибку и доступную альтернативу. Нативная сборка допустима при подготовке поставки; её наличие на VDI не предполагать.
- [ ] Проверить установленный архиватор как возможный запасной путь, не делая его обязательным и не передавая пароль аргументом процесса.

### 3. Найти браузерный маршрут

- [ ] Подготовить маленькую диагностическую страницу с Canvas, счётчиком кадров, кнопками паузы и fullscreen; она не передаёт рабочих файлов.
- [ ] Открыть её доступным способом через существующий JupyterHub: активная отдельная страница/файловый маршрут либо разрешённый встроенный вывод. Проверить выполнение JS фактически.
- [ ] Проверить загрузку локальных JS/данных, CSP, разрешения iframe, worker и WASM при планируемом использовании. Для каждого средства указать «работает / ограничено / не проверено».
- [ ] Проверить ручной вход в fullscreen и обычное окно. Измерить CSS viewport, Canvas backing size, `devicePixelRatio` и пиксели на хосте.
- [ ] Проверить повторное открытие и перезапуск, скрытие вкладки, остановку. На этом этапе обнаружить возможное замедление фоновой вкладки.
- [ ] Убедиться, что страницу и подготовленные данные можно открыть без CDN, публичного сайта кодека и нового внешнего сервиса. Используется существующий маршрут JupyterHub; его ограничения не отключаются.

### 4. Зафиксировать исходную скорость

- [ ] Создать небольшой детерминированный бинарный файл и каталог с Unicode-именами; сохранить исходные хеши в тестовом манифесте.
- [ ] Выполнить локальный round-trip и затем реальную VDI-передачу `code.py` → браузер → `qr.py` в отдельный пустой каталог.
- [ ] Начать с текущих значений: один V40-L, чанк 2800, 600 мс. Сохранить разрешение и размер QR после CSS-масштабирования.
- [ ] Зафиксировать время подготовки HTML, его размер, время передачи, память и совпадение SHA-256. Для каталога отдельно проверить содержимое tar.xz: текущий приёмник сам его не распаковывает.
- [ ] Для первого замера взять 64–256 КиБ, чтобы штатный таймаут 300 с не обрезал заведомо долгую передачу. Больший тест выполнять с явно увеличенным таймаутом и записанными параметрами.
- [ ] Выполнить три коротких прогона; сохранить также неудачи. Не выдавать этот замер нешифрованного прототипа за прямое сравнение с будущим парольным форматом.

## Артефакты реализации

- `docs/reports/environment.md`: версии, ресурсы, способ запуска/открытия, ограничения и список проверенных пакетов.
- `benchmarks/baseline/`: конфигурации и результаты без рабочих файлов пользователя.
- Диагностическая страница и небольшая инструкция её открытия, пригодные для последующего Э01.
- Решение о первичном маршруте плеера и запасном оконном показе; при отсутствии рабочего маршрута — конкретная блокирующая причина.

Эти пути — ожидаемые результаты будущей итерации, сейчас отчёты не созданы.

## Проверки и критерии готовности

- [ ] Python 3.10 запускается в целевом JupyterHub, зависимости базового прототипа устанавливаются выбранным способом.
- [ ] Есть подтверждённый запуск активного HTML и передача подготовленных ресурсов из Python-окружения в браузер.
- [ ] Тестовый файл восстановлен через реальный экран VDI с совпадением SHA-256; параметры воспроизводимы.
- [ ] Известен фактический размер кадра на хосте при Full HD. Неизвестные настройки явно отмечены.
- [ ] Для И02, Э01 и проверки libcimbar хватает данных о среде; неподтверждённые дополнительные возможности не выданы за работающие.

Если VDI пока недоступен, завершить локальную диагностику и подготовку инструкций. И00 остаётся частично выполненной до реального запуска; локальные задачи И01/И02 могут продолжаться.
