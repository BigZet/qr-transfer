# И02. Сжатие, парольная защита и распаковка

[Общий план](../../IMPLEMENTATION_PLAN.md) · Вход: [И00](00-environment-baseline.md), [И01](01-core-protocol.md) · Далее: [И03](03-browser-mono-mvp.md)

Статус: **реализовано и проверено локально; приёмка в JupyterHub открыта**. [Инструкция](../usage/iteration-02.md) · [Результаты](../reports/container.md) · [Спецификация](../specs/container.md). Цель — реализовать общий защищённый объект для любого визуального транспорта и точное восстановление исходного дерева.

## Результат

Файл или каталог превращается в зашифрованный архив со скрытыми именами. Полученный архив можно проверить и распаковать на хосте; ошибка пароля не требует новой передачи. Эта итерация проверяется на дисковых файлах, без браузера.

## Задачи

### 1. Выбрать и закрепить контейнер

- [ ] Проверить доступную в зеркале версию `py7zr`, Python 3.10, транзитивные зависимости и поддержку выбранных параметров на обеих ОС.
- [x] Реализовать кандидат 7z с LZMA2 и AES-256, явно включить шифрование заголовка и проверить невозможность получить исходные имена без пароля.
- [x] При явном задании compression filters убедиться, что в цепочке осталось шифрование. Наличие password-параметра проверяется реальной попыткой чтения, а не только конфигурацией.
- [x] Сравнить сильные уровни/словарь на тексте, каталоге и уже сжатом файле. Выбрать профиль `max` в пределах доступной памяти, сохранить точные параметры и результаты.
- [x] Установленный архиватор рассматривать как альтернативный backend только при проверенном скрытом вводе и отсутствии пароля в argv/логах.
- [x] Если ни один 7z-backend не проходит требования, оформить решение о другом формате до его реализации. Для `tar.xz + AEAD` отдельно специфицировать готовую криптобиблиотеку, KDF и его ограничения, соль, nonce, теги, версию, обработку больших файлов и тестовые векторы. Незашифрованный архив не является запасным рабочим режимом.

Документация `py7zr` описывает password, отдельное включение encrypted header, LZMA2 и фильтр шифрования; точное поведение проверяется для закреплённой версии. Источник: [API py7zr](https://py7zr.readthedocs.io/en/latest/api.html).

### 2. Подготовить данные

- [x] Сжимать весь объект до транспортного разбиения. Один обычный файл, пустой файл и каталог используют один и тот же контейнерный процесс.
- [x] Создать внутренний манифест: версия, относительные пути, типы записей, размеры, SHA-256 файлов и пустые каталоги. Исходные пути вне выбранного корня не сохраняются.
- [x] Разместить пользовательское дерево и служебный манифест в разных пространствах имён контейнера, чтобы пользовательский файл не мог заменить манифест.
- [x] Определить правила ссылок и специальных файлов. Для первой поставки отклонять символьные/жёсткие ссылки и устройства с понятным сообщением; не следовать ссылке незаметно за пределы дерева.
- [x] Определить явные исключения. Старые фильтры `.git`/кэшей не переносить как скрытую потерю данных: по умолчанию сохранять обычные файлы либо заранее показывать выбранную пользователем политику исключений.
- [x] Обнаруживать изменение исходных файлов во время упаковки. Манифест должен описывать именно упакованные байты; при невозможности согласованного чтения завершать подготовку ошибкой и предлагать повтор.
- [x] Обеспечить нейтральное имя выходного архива и технический дескриптор с размером/SHA-256. Итоговый архив неизменяем; повторный показ не запускает сжатие заново.
- [x] Писать выход через временный файл в каталоге назначения и завершать атомарно. Отмена освобождает незавершённые ресурсы и не удаляет пользовательский исходник.

### 3. Ввод пароля и жизненный цикл

- [ ] Скрытый ввод на отправителе с подтверждением; пустой пароль отклонять. Проверить выбранный в И00 интерфейс JupyterHub.
- [x] API принимает пароль только во время вызова; он не попадает в сериализуемую конфигурацию, исключения, командную историю, HTML или QR.
- [x] Приёмник запрашивает пароль после проверки полного архива; возможен повторный ввод и отдельная команда распаковки уже принятого объекта.
- [x] Не сохранять пароль в состоянии сессии. Не обещать гарантированное стирание Python-строки из RAM.
- [x] Открытые метаданные не содержат исходных имён. Публичный SHA-256 относится к зашифрованным байтам; исходные хеши остаются во внутреннем манифесте.
- [x] Ошибку пароля и повреждение контейнера показывать без ложной уверенности, если библиотека не умеет надёжно различить причины.

### 4. Проверка и безопасная распаковка

- [x] До распаковки проверить длину и SHA-256 принятого архива по согласованному дескриптору.
- [x] После ввода пароля проверить список записей, относительность путей, отсутствие `..`, абсолютных путей, дисковых префиксов/UNC и ссылок. Проверить особенности имён Windows, включая альтернативные потоки и зарезервированные имена.
- [x] Обнаруживать дубликаты, case-insensitive и Unicode-конфликты до записи результата. Не менять имена молча; несовместимое дерево даёт точный отчёт.
- [x] Распаковывать в новый временный каталог на той же файловой системе, без существующих пользовательских файлов и ссылок в пути.
- [x] Применять лимиты количества файлов, итогового размера и доступного диска. Ограничивать фактически записываемые байты, а не доверять только заявленным размерам архива; проверить, что выбранный backend позволяет это обеспечить.
- [x] Сверить распакованное дерево с внутренним манифестом: нет лишних/пропущенных записей, совпадают имена, размеры и SHA-256.
- [x] Только после всех проверок публиковать готовый каталог. Занятое имя результата не перезаписывать; предложить/создать новый явно показанный путь.
- [x] При ошибке сохранить проверенный зашифрованный архив и состояние, а частичную распаковку отделить от готового результата. Повторная попытка не требует экрана.

## Артефакты реализации

- Модуль контейнера с prepare/inspect/extract и скрытым вводом.
- `docs/specs/container.md`: формат, манифест, параметры сжатия/шифрования, лимиты и правила путей.
- Тестовый набор файлов/каталогов и негативных архивов; отчёт о размере, времени и RAM разных профилей.
- Зафиксированные версии и инструкция установки backend из зеркала.

## Проверки и критерии готовности

- [x] Пустой/маленький/случайный/уже сжатый файл, вложенный каталог, пустые каталоги и Unicode проходят точное восстановление.
- [x] Без пароля содержимое и исходные имена недоступны; неверный пароль не создаёт готового результата, правильный повтор работает.
- [x] Пароль отсутствует в HTML-заготовках, QR-метаданных, конфигурации, логах, состоянии и рекомендуемых командах.
- [x] Повреждение архива/манифеста, небезопасные пути, ссылки, коллизии имён, нехватка диска и превышение лимитов не приводят к записи вне выделенного каталога или ложному успеху.
- [ ] Профиль сильного сжатия укладывается в измеренный бюджет памяти JupyterHub и восстанавливается на хосте под целевым Python.
- [x] Ограничения обычного парольного 7z описаны: контроль транспортных ошибок не заявлен криптографической аутентификацией отправителя.

Сохранение прав ОС, ACL и всех файловых метаданных не входит в гарантию побайтного восстановления файлов; поддерживаемый набор метаданных явно перечислить в спецификации.

## Уточнения приёмки

Парольный backend — только py7zr 1.1.3; системный архиватор и альтернативный формат не подключались, потому что выбранный backend прошёл локальные требования. Скрытый ввод реализован и проверен на Windows, но соответствующий пункт остаётся открытым до проверки терминала JupyterHub. Max выбран по локальному сравнению; попадание в реальную квоту JupyterHub ещё не подтверждено. Готовые Linux/Python 3.10 wheels скачаны из публичного PyPI, доступность зеркала и Linux runtime не объявляются проверенными.
