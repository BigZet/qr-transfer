# Э01. Независимый эксперимент передачи цветов через VDI

[Общий план](../../IMPLEMENTATION_PLAN.md) · Подготовка: [И00](../iterations/00-environment-baseline.md) · Использование результата: [И06 RGB-QR](../iterations/06-rgb-qr.md), [И07 libcimbar](../iterations/07-cimbar.md), [И08 профили](../iterations/08-performance-profiles.md)

Статус: **запланировано; измерений данного VDI пока нет**. Эксперимент проводится отдельно от передачи файлов. Он не требует готовых шифрования, AQR2, FEC или цветного QR-декодера.

## 1. Вопрос эксперимента

Какие цветовые и пространственные детали проходят по фактическому пути **HTML/Canvas в браузере VDI → удалённое отображение → снимок экрана хоста**? Проверить прежде всего 8 цветов и определить полезный размер элемента и частоту смены.

Крупные однотонные поля могут сохраняться отлично, а мелкая цветная сетка — размываться. Поэтому отдельно измеряем палитру, мелкие неподвижные элементы и быстро меняющиеся узоры. Декодирование QR добавляется только после этого, чтобы разделить свойства канала и ошибки конкретного декодера.

Эксперимент не передаёт рабочие файлы: используется известный обеим сторонам синтетический набор. Знание ожидаемых битов служит измерению ошибок и не является способом восстановления пользовательского архива.

## 2. Независимые инструменты

Создать в рамках эксперимента:

| Артефакт | Назначение |
| --- | --- |
| `experiments/vdi_color/generate.py` | Генерация тестовых случаев, известной последовательности и локальных ресурсов плеера под Python 3.10 |
| `experiments/vdi_color/player.html` и JS | Палитры/сетки, static/animation, управление, экспорт конфигурации без внешних ресурсов |
| `experiments/vdi_color/capture.py` | ROI-захват на хосте, временные метки и ограниченная запись снимков |
| `experiments/vdi_color/analyze.py` | Геометрия, распознавание цвета, сравнение с эталоном, CSV/JSON и графики |
| `experiments/vdi_color/cases/` | Версионированные определения палитр, размеров, seed и ожидаемых данных |
| `docs/reports/vdi-color/` | Будущие отчёты и небольшие выбранные примеры кадров |

Эти инструменты **ещё предстоит реализовать**. На старте достаточно Python, Canvas, захвата и операций над массивами. Для надёжного ID кадра можно использовать маленькие монохромные QR существующего генератора; основной цветной массив от QR не зависит.

Одинаковую версию cases/генератора заранее разместить в нашей поставке на обеих сторонах. Генератор должен давать одинаковую последовательность на Python 3.10/3.12 и в JS, если JS её создаёт сам: зафиксировать алгоритм и golden vectors либо поставлять уже готовые эталонные массивы. Не передавать ожидаемые данные по отдельному VDI → host каналу во время теста.

## 3. Условия и конфигурация

Для каждого прогона записать:

- ID/версию теста, seed, палитру и явное соответствие цвета логическим битам.
- ОС/браузер/версию, Python, используемый frontend и маршрут JupyterHub.
- Разрешение VDI, размер окна/viewport, `devicePixelRatio`, масштаб браузера/ОС/клиента и фактический размер снимка хоста.
- Известные настройки качества/графики VDI. Если кодек неизвестен, оставить `unknown`.
- ROI, номинальный и измеренный размер элемента, расположение тестовой области и наличие масштабирования.
- Заданную частоту, длительность, режим обновления всей области/частей, фактический захват и время обработки.

Начальная конфигурация: Full HD, штатные настройки VDI, масштаб браузера 100%, fullscreen при доступности. Если fullscreen недоступен, тест рассчитан на реальный viewport. Не считать масштаб 100% доказательством соответствия одного Canvas-пикселя одному пикселю на хосте — это измеряется.

Дополнительные режимы: доступные масштабы 125/150%, уменьшение окна, 4K и переход к 1080p. Сначала получить результат в одном воспроизводимом базовом режиме, затем менять по одному фактору.

## 4. Палитры и узоры

### Палитры

| Режим | Начальная палитра | Информационная ёмкость |
| --- | --- | --- |
| Моно | Чёрный/белый | 1 бит на элемент |
| 4 цвета | Четыре комбинации двух логических плоскостей, с зафиксированным отображением в RGB | 2 бита на элемент |
| 8 цветов | RGB-куб: чёрный, красный, зелёный, синий, cyan, magenta, yellow, белый | 3 бита на элемент |

Для RGB-8 можно начать с значений каналов 0/255 и независимых порогов. Альтернативная палитра допустима после измерения кластеров: сохранить её как новый профиль и восстановить логические биты по таблице цветов, а не считать её физическими R/G/B-плоскостями автоматически.

16 цветов — необязательное продолжение после убедительного результата 8; оно не задерживает основной вывод эксперимента.

### Узоры

1. Крупные равномерные поля всех цветов, повторённые в центре и по краям.
2. Горизонтальные/вертикальные чередования и шахматные узоры для разных пар цветов.
3. Случайная равномерная сетка с высокой долей смен между соседями. Она приближает нагрузку зашифрованных данных и не состоит из одного многократно повторённого маленького тайла.
4. Статическая случайная сетка и последовательность новых сеток той же плотности.
5. Раздельное обновление левой/правой половины и одновременное обновление всей площади при одинаковом числе новых элементов в секунду.
6. Дополнительные QR-подобные матрицы с тихими зонами и служебными узорами; полный RGB-QR round-trip выполняется в И06.

Размеры элементов для первичного поиска: **8, 6, 5, 4, 3, 2 пикселя в источнике**. Измеренные размеры на хосте могут быть другими; оба значения сохраняются. Нельзя считать, что порог для цветной квадратной ячейки автоматически подходит плитке cimbar с рисунком внутри.

## 5. Пошаговое проведение

### А. Контроль без VDI

- [ ] Подать исходные тестовые PNG прямо в анализатор: все цвета, координаты и ожидаемые биты должны совпасть точно.
- [ ] Запустить тот же плеер локально на хосте и захватить экран. Выделить ошибки самого Canvas/масштаба/захвата до добавления VDI.
- [ ] Проверить эталонные последовательности и идентификацию кадров на разных целевых версиях Python.

### Б. Калибровка геометрии и крупных цветов на VDI

- [ ] Открыть плеер тем же способом, что будет использоваться при передаче. Выбрать ROI и определить масштаб по контрастным опорным маркерам.
- [ ] Показать крупные цветовые поля минимум несколько секунд; сохранить динамику первых кадров и установившийся участок отдельно.
- [ ] Оценить центры/разброс RGB-кластеров, различимость цветов и зависимость от положения на экране.
- [ ] Повторить калибровку в начале и конце серии, чтобы заметить дрейф/изменение настроек.

### В. Пространственный тест без смены кадра

- [ ] Для 2/4/8 цветов пройти размеры от 8 до 2 px: полосы, шахматный и случайный узор, центр и края рабочей области.
- [ ] Каждый образец удерживать, например, 2 с; первые 0,5 с анализировать как установление изображения, остальное — отдельно как стабильный участок.
- [ ] Сравнить чтение центра модуля, среднего центральной области и всего элемента. Проверить, сколько пикселей остаётся при маленьком модуле после исключения границ.
- [ ] Подобрать геометрию на калибровочных маркерах, а не двигать сетку по известным ожидаемым битам каждого тестового кадра.
- [ ] Отобрать максимум два перспективных размера для динамики. Размер, различимый только после долгого удержания, пометить отдельно.

### Г. Динамический тест

- [ ] Для отобранных размеров сравнить 2/4/8 цветов при 2, 5, 10, 15 и 30 обновлениях/с. Начинать с низкой частоты; при устойчивом ухудшении остановить повышение и сохранить результат.
- [ ] Скрининг — примерно 30 с на конфигурацию. Для финальных 2–3 конфигураций — три независимых серии с разными seed и начальной фазой захвата, минимум 60 с каждая.
- [ ] Сравнить смену всей области и чередование двух частей при сопоставимом потоке новых элементов. Для частей нужны независимые frame ID.
- [ ] Проверить частоту захвата, достаточную для наблюдения нескольких состояний; записывать пропуски самого capture отдельно. Заданные 30 fps приёмника не доказывают 30 обработанных снимков/с.
- [ ] На каждом прогоне сохранить ограниченную выборку lossless PNG и числовые результаты для всех обработанных снимков. Видео с потерями не использовать как единственный источник оценки цветовых ошибок.

Не требуется полный декартов перебор всех масштабов, палитр и частот. Сначала скрининг, затем подробная проверка кандидатов; точный список выполненных и пропущенных случаев входит в отчёт.

### Д. Проверка смены условий

- [ ] Для финального кандидата изменить разрешение/масштаб, затем восстановить исходный режим и повторить калибровку.
- [ ] Проверить окно без fullscreen и края области, если такие условия встречаются в работе.
- [ ] При доступном 4K повторить лучшие Full HD настройки и более плотный профиль; результат не заменяет Full HD.

## 6. Кадры, смешанные обновления и эталон

Каждый тест имеет `case_id`, `frame_id`, seed и хеш ожидаемого массива. В динамике ID должен быть прочитан из самого захваченного изображения — номера browser timer недостаточно.

- Разместить независимые контрастные ID/маркеры у нескольких частей тестовой области; для чередования половин каждой назначить свой ID.
- Несовпадение ID разных областей помечать как смешанный снимок. Для окончательной диагностики добавить региональные ID/контрольные образцы по высоте, поскольку два одинаковых угловых ID не гарантируют отсутствие старой полосы внутри.
- Снимки без читаемого ID не сравнивать с угаданным «ближайшим» эталоном и не выбирать seed по минимальной ошибке. Считать их отдельной потерей/неопределённым снимком.
- Для корректно определённого состояния сравнивать каждый элемент с заранее известным цветом. Смешанные снимки сохранять в общих потерях; нельзя исключить их из знаменателя успеха канала и оставить только удобные кадры.
- В отчёте указать диагностические накладные расходы маркеров. Они не равны будущим расходам полезного файлового транспорта.

## 7. Анализ и метрики

### Классификаторы

Сравнить независимые пороги каналов с классификацией по ближайшему измеренному центру палитры. Если расстояния RGB неудовлетворительны, проверить нормировку/другое цветовое пространство как отдельный вариант. Калибровать только на выделенных образцах; качество оценивать на других seed и кадрах, не участвовавших в настройке.

| Метрика | Как считать |
| --- | --- |
| Матрица ошибок цветов | Для каждого ожидаемого цвета число наблюдений каждого распознанного цвета; отдельно неопределённые |
| `symbol_error_rate` | Ошибочно классифицированные элементы / элементы с известным эталоном; неопределённые учесть явно |
| `bit_error_rate` по слою | Различающиеся логические биты / сравниваемые биты при фиксированной таблице палитры |
| Геометрия | Масштаб/смещение, неодинаковость шага, ошибки по центру/краям и направлению полос |
| Частота новых состояний | Число различных достоверно прочитанных frame/region ID / время захвата |
| Пропуски/повторы/смешанные | Доли среди всех попыток захвата, с отдельным счётчиком потерь анализатора |
| Кластеры | Центры, разброс и расстояния цветов в калибровке и контрольной выборке |
| Цена анализа | Время capture/classify, CPU/RAM и объём записанной выборки |

Номинальные 1/2/3 бита на элемент показать отдельно. Даже `3 × число элементов × FPS` — только ёмкость до служебных расходов/ECC/потерь, а не скорость принятого архива. Универсального BER-порога, гарантирующего чтение QR, здесь не назначать: распределение ошибок и повреждение служебных узоров существенны.

## 8. Решение по результатам

| Наблюдение | Следующее действие |
| --- | --- |
| 8 цветов различимы в мелкой динамической сетке на контрольных seed | Перенести палитру/геометрию/частоты в И06, проверить сквозной RGB-QR |
| Большие поля различимы, мелкие смешиваются | Укрупнить модуль, уменьшить QR-версию, проверить центральную выборку и 4 цвета |
| Static читается, animation резко теряется | Снизить частоту, проверить чередование областей и работу VDI при случайном узоре |
| Независимые RGB-пороги плохи, кластеры разделимы | Восстанавливать логические плоскости через измеренную палитру |
| Один слой существенно хуже | Сравнить 2 слоя и FEC, не объявлять полный множитель 3× |
| Ни 4, ни 8 цветов не дают пригодной динамики в доступных режимах | Сохранить данные/ограничения, выбрать mono для этой конфигурации, отдельно оценить штатный cimbar |

Вывод «цвет сохраняется» допускается только с указанием размера элемента, частоты, положения и условий канала. Окончательная рекомендация цвета принимается по времени полного файла в И06/И08.

## 9. Отчёт и критерии завершения

Отчёт должен содержать конфигурацию, выполненную матрицу, исходные CSV/JSON, матрицы ошибок, несколько lossless-кропов, повторные серии, выбранные настройки и ограничения. Отсутствие искажений на сохранённой выборке не гарантирует их отсутствие во всех будущих кадрах.

- [ ] Контрольные изображения анализируются правильно без VDI; эталон одинаков на обеих сторонах.
- [ ] На реальном VDI выполнены static и animation для 2/4/8 цветов с несколькими размерами элементов и частотами.
- [ ] Есть отдельные счётчики пространственных ошибок, потерь/смешивания кадров и отставания анализатора.
- [ ] Настройка палитры и итоговая оценка используют разные данные; финальные серии повторены.
- [ ] Результат воспроизводим по сохранённым cases/config/version и содержит решение для И06/И07, даже если оно отрицательное.
- [ ] В отчёте нет рабочего содержимого пользователя; сохраняемые изображения ограничены тестовым ROI.

Э01 завершён после получения и анализа измерений. Сам этот документ — план эксперимента, он не подтверждает сохранность восьми цветов на данном VDI.
